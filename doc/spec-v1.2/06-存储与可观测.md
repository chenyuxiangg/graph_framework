## 6.1 范围、存储选型与硬约束

**一句话结论**：v1 用**单进程单写线程 + WAL 的 SQLite** 落全部 trace；00 的 6 类不可丢事件走无损通道，`Streaming` 走可丢通道并在写线程按 100ms 聚合；存储只做**可观测与回放**，不做断点续跑。

### 6.1.1 定位

| 项 | v1 规定 |
|---|---|
| 存什么 | run 元数据、实例快照、状态迁移、门控结果、流式聚合分段、统一事件序号、图定义原文 |
| 不存什么 | 在飞任务状态快照（不做 resume）、Input Buffer 全量、Python 进程状态、checkpoint（M-06 只保留"审计 trace"语义） |
| 用途 | ① AC-03 trace 可回放；② 失败诊断（`instances.error`/traceback）；③ AC-01/02/05/06/08 的 SQL/CLI 断言；④ 崩溃后 run 状态标定 |
| 明确不做 | 断点续跑、跨机共享 DB、分布式 seq、自动归档清理（v1 保留全部） |

### 6.1.2 存储栈

| 组件 | 方案 | 依据 |
|---|---|---|
| 引擎 | SQLite（`rusqlite` + `bundled`） | 决策记录 §3.4；`_spike/REPORT.md` §3.6 已验证 |
| 日志模式 | `journal_mode=WAL` | 读（`zgraph trace`）与写（`zgraph run`）不互斥 |
| 同步级别 | `synchronous=NORMAL` | 进程崩溃安全（I6 目标）；**掉电可能丢最后若干已提交事务**（已声明，§6.1.3 S4） |
| 写模型 | **单写线程**（`std::thread`），批量事务 | spike：异步管道 3.61 µs/条、单批最大 3 ms；同步 autocommit 13.4 µs/条不可接受 |
| 读模型 | 任意只读连接（CLI `trace`），`busy_timeout` 等待 | WAL 快照读，不阻塞写 |
| 多进程 | 同机多进程允许（WAL + `busy_timeout` + `BEGIN IMMEDIATE`）；**不支持跨机/网络盘** | v1 单机假设 |

### 6.1.3 硬约束（MUST）

| # | 约束 | 依据 |
|---|---|---|
| S1 | 00 §0.6 I6 的 6 类事件（`RunStarted`/`Transition`/`GateResult`/`NodeTimedOut`/`NodeAbandoned`/`RunFinished`）**永不因背压丢弃**：生产侧 `send().await`（满则等待） | 00 §0.6 I6；03 §3.12 |
| S2 | `Streaming` 可丢：`try_send` + `RunMetrics.streaming_dropped` 单一计数；丢弃不影响控制流 | 00 §0.3/§0.6；03 §3.12；04 §4.2 |
| S3 | 事件循环线程**永不**做 SQLite 写；所有写只在写线程 | 00 §0.6 I8；spike §3.6 |
| S4 | trace 是**可观测数据**，不是恢复依据；进程崩溃后不合成事件、不改写历史行 | §6.8 |
| S5 | run 终态唯一（`RunFinished` 恰好一次，I5）；恢复标定是**唯一**允许的"事后改状态"路径，且必须留 `runs.interrupted=1` | 00 §0.6 I5；§6.8 |
| S6 | `events.kind` 值域 == 00 §0.3 `TraceEvent` 七类；`runs.status`/`instances.status` 值域 == 00 §0.3 枚举；`runs.error_code` 只允许 00 §0.4 的码；**本分册不新增任何领域枚举/错误码** | 00 §0.3/§0.4 |

### 6.1.4 生产矩阵（谁产出哪个 `TraceEvent`）

| `TraceEvent`（00 §0.3） | 生产者 | 通道 | 可丢 | 落库 |
|---|---|---|---|---|
| `RunStarted` | 调度器（run 启动） | 无损 | ❌ | `events` + `runs`(insert，同事务) |
| `Transition` | 调度器（01 §1.2 矩阵每次迁移） | 无损 | ❌ | `events` + `transitions` + `instances`(upsert) |
| `GateResult` | 调度器（publish 应用时逐边） | 无损 | ❌ | `events` + `gate_results` |
| `NodeTimedOut` | 调度器（实例超时判定） | 无损 | ❌ | `events`（仅信封，payload 含 `elapsed_ms`） |
| `NodeAbandoned` | **deprecated：v2 不产生（D1）**；仅兼容读取旧 trace | 无损 | ❌ | `events`（仅信封，payload 含 `at`） |
| `RunFinished` | 调度器（终态，恰好一次） | 无损 | ❌ | `events` + `runs`(update，同事务) |
| `Streaming` | 节点 / Harness（`NodeContext.emit`，04 §4.2） | 可丢 | ✅ | `events` + `streaming_events`（**写线程聚合后**，§6.5） |

> `NodeTimedOut` 字段极少且不参与逐条查询主路径，**只落 `events` 信封**（不做明细表）；查询时 `JOIN instances ON events.instance_id` 取 `node_id`。`NodeAbandoned` 在 v2 不产生，保留仅为旧 trace 兼容读取。

## 6.2 Schema（DDL v1，可直接执行）

**一句话结论**：6 张主表（`runs`/`instances`/`events`/`transitions`/`gate_results`/`streaming_events`）+ 2 张辅助表（`schema_migrations`/`graphs`）；`events.seq` 是**全局唯一序**，明细表以 `seq` 1:1 关联。

### 6.2.1 连接级 PRAGMA（每个连接打开后立即执行）

```sql
PRAGMA journal_mode = WAL;          -- 持久属性（写入 DB 文件头）
PRAGMA synchronous = NORMAL;        -- 进程崩溃安全；掉电风险见 §6.1.3 S4
PRAGMA foreign_keys = ON;           -- 每连接必须显式开启
PRAGMA busy_timeout = 5000;         -- 多进程/读写竞争等待上限（ms）
PRAGMA wal_autocheckpoint = 1000;   -- 每 1000 页自动 checkpoint
PRAGMA temp_store = MEMORY;         -- 排序临时表（trace 查询）不进磁盘
```

| 常量 | 值 | 说明 |
|---|---|---|
| `DB_BUSY_TIMEOUT_MS` | `5000` | 与 `SHUTDOWN_GRACE_MS` 同量级；超时 → `SQLITE_BUSY` |
| `DB_WRITE_RETRY` | `3` | 写线程遇 `SQLITE_BUSY` 的重试次数（每次间隔 50 ms） |
| `DB_CHECKPOINT_ON_CLOSE` | 开启 | 关闭前 `PRAGMA wal_checkpoint(TRUNCATE)`，避免 `-wal` 残留 |

### 6.2.2 版本表与迁移

```sql
CREATE TABLE IF NOT EXISTS schema_migrations (
  version     INTEGER PRIMARY KEY,
  description TEXT    NOT NULL,
  applied_at  TEXT    NOT NULL              -- UTC RFC3339
);

-- 快速版本检查：PRAGMA user_version = 3（与 schema_migrations 最新行一致；M6 起，REV-049）
```

> **M6 口径（REV-049，ISSUE-087）**：trace schema 当前为 **v3**（`TRACE_SCHEMA_VERSION = 3`）。新库由**单事务**建当前 DDL 并写 `schema_migrations` 1/2/3 三行；旧库升级为**逐版本循环**（v1→v2→v3），每次迁移写本次版本行——**不 backfill 历史版本行**（审计行从升级起点起，M6 实现口径）。迁移细节见 §6.7。

### 6.2.4 run 主表

```sql
CREATE TABLE IF NOT EXISTS runs (
  run_id           TEXT PRIMARY KEY,        -- UUIDv7
  graph_hash       TEXT NOT NULL REFERENCES graphs(graph_hash),
  status           TEXT NOT NULL
                   CHECK (status IN ('Running','Paused','Completed','Failed','Cancelled')),
  user_id          TEXT,
  started_at       TEXT NOT NULL,
  finished_at      TEXT,                    -- 终态时间；中断标定后保持 NULL（§6.8）
  entry_inputs     TEXT,                    -- JSON: {node_id: {port: value}}（RunSpec，非事件载荷）
  output_json      TEXT,                    -- JSON: run_output（01 §1.9；失败/中断为 NULL）
  error_code       TEXT,                    -- TraceError.code；仅 00 §0.4 的码；NULL 表示无
  error_message    TEXT,                    -- TraceError.message（人类可读）
  owner_pid        INTEGER,                 -- 进程号（崩溃标定用）
  owner_host       TEXT,                    -- 主机名（v1 恒为本机；保留列）
  heartbeat_at     TEXT,                    -- 写线程每 ≤5s 刷新
  interrupted      INTEGER NOT NULL DEFAULT 0 CHECK (interrupted IN (0,1)),
  recovered_at     TEXT,                    -- 最近一次中止标定时间
  last_seq         INTEGER NOT NULL DEFAULT 0,
  event_count      INTEGER NOT NULL DEFAULT 0,
  streaming_dropped INTEGER NOT NULL DEFAULT 0,  -- RunMetrics.streaming_dropped
  abandoned_tasks  INTEGER NOT NULL DEFAULT 0,   -- RunMetrics.abandoned_tasks（D1：v2 恒 0）
  trace_backpressure INTEGER NOT NULL DEFAULT 0, -- RunMetrics.trace_backpressure（累计等待 ms）
  -- v2 增量列（D5/D9/§8.2）：L2 重放与 worker kill 指标
  seed             INTEGER NOT NULL DEFAULT 0,   -- run 载荷 seed（D5；RunSpec.options.seed）
  worker_versions_json TEXT,                      -- L2 绑定因子：worker/SDK/Python 版本（D9；M5 接线）
  model_params_json    TEXT,                      -- L2 绑定因子：模型参数快照（D9；M5 接线）
  record_mode      TEXT,                          -- L2 记录模式：none|hash|full（小写；D9）
  killed_workers   INTEGER NOT NULL DEFAULT 0,    -- RunMetrics.killed_workers（D1/§8.2）
  global_vars_json TEXT                           -- v3：RunStarted.global_vars（canonical JSON；M6/ISSUE-087）
);

CREATE INDEX IF NOT EXISTS idx_runs_status_started ON runs(status, started_at);
CREATE INDEX IF NOT EXISTS idx_runs_unfinished ON runs(status) WHERE status IN ('Running','Paused');
```

> `RunFinished.metrics`（00 §0.3 `RunMetrics`）四项分别落 `streaming_dropped` / `abandoned_tasks`（恒 0）/ `trace_backpressure` / `killed_workers`；`RunFinished` 事件与本行 update 同事务，保证事件-快照一致。
>
> **v2 列（M2 已建，D5/D9；M5 写入口径，REV-028）**：`seed`（u64，来自 `RunSpec.options.seed`）、`record_mode`（取值域固定为小写 `none`/`hash`/`full`，未知值回退 `hash`；M2 未加 CHECK 约束，读取按 canonical 枚举解析——ISSUE-037）、`killed_workers`（§6.4.4）、`worker_versions_json`/`model_params_json`（M2 建列；**写入仍未接线、保持 NULL——ISSUE-082 pending，待后续合并**）。**写入者**：`record_mode`/`seed` 由 CLI `zgraph run` 经 `RunSpec.options` 透传、内核落库（默认 `record_mode=hash`）；`zgraph replay` 只读，不写这些列。
>
> **v3 列 `global_vars_json`（M6 已建并接线，REV-049；ISSUE-087 fixed）**：`TEXT`，内容是 `RunStarted.global_vars` 的 **canonical JSON**（对象键递归排序，规避工作区 `serde_json/preserve_order` 的插入序；非 object 视为不可恢复写错误）。**写入者**：CLI `TraceBridge` 在启动前抓 `RunSpec.global_vars` 覆盖 `RunStarted` 后落库（kernel 契约未改）。**CLI 无 `--global-vars` 参数**（06 §6.10.3 未定义该参数，不为它新增契约）：`zgraph run` 记录 `{}`，非空值只由库 API（bridge `with_snapshot`）覆盖。v3 之前的历史 run 该列为 `NULL`（读侧 `RunRow.global_vars = None`），L2 replay 以空 map + stderr 告警兼容（§6.10.7）。
>
> **API 兼容备注（REV-049）**：`RunStartedInfo` 新增必填 `global_vars`、`RunRow` 新增 `global_vars`，对仓内库消费者（trace/cli）属 **source-breaking**；v0.1 未冻结、仓内构造点已全部更新。

### 6.2.5 实例快照表

```sql
CREATE TABLE IF NOT EXISTS instances (
```

#### 6.2.5.1 `NodeError` → JSON canonical 形状（ISSUE-053，M2 冻结；M5 ISSUE-066 只增 `NodeWorker` 证据键）

`instances.error` 与 `transitions.error` 存放**同一形状**的 JSON 对象（由 CLI 桥接层 `node_error_json` 逐变体展开；内核类型无 serde 派生）。**这是对外契约**：AC-05/AC-06 与 `zgraph trace --json` / CLI 回放依赖它，M3 可复用。

```json
{"code": "<00 §0.4 / §8.2 顶层错误码>", "message": "<NodeError Display 文本>", "kind": "<变体名>", "...": "变体附加字段"}
```

| `kind` | 对应 `NodeError` | 附加字段（有则必现） |
|---|---|---|
| `BusinessError` | `BusinessError{code,message}` | `business_code`: 载荷业务码（`NODE_RETURN_NOT_DICT`/`NODE_RETURN_NOT_JSON`/`BIZ_*`） |
| `PythonException` | `PythonException{message,traceback}` | `exception`: 异常摘要；`traceback`: `format_exc()` 全文（**不截断**） |
| `Timeout` | `Timeout{elapsed_ms}` | `elapsed_ms`: u64 |
| `Cancelled` | `Cancelled` | — |
| `Harness` | `Harness{kind,detail}` | `harness_kind`: `HarnessErrorKind` 名（如 `LlmTimeout`）；`detail`: JSON |
| `Config` | `Config{message}` | — |
| `Internal` | `Internal{message}` | — |
| `NodeWorker` | `NodeWorker{kind, signal, exit_code, stderr_tail}`（D10 + M5 ISSUE-066/REV-031） | `worker_kind`: `Handshake`/`Protocol`/`Import`/`Crash`（§8.2）；**仅崩溃路径且 supervisor 观察到进程退出证据时**追加可选 `signal`（Unix 信号编号 i32；非 Unix 省略）、`exit_code`（非约定退出码 i32；被信号杀死时省略）、`stderr_tail`（stderr 尾部，≤1 KiB，按 UTF-8 字符边界截断；空白/无内容省略） |

- `code` 恒为 `NodeError::code()` 的结果（顶层码，如 `NODE_PYTHON_EXCEPTION`、`NODE_WORKER_IMPORT`、`HARNESS_LLM_TIMEOUT`）；`message` 是 `Display` 文本。
- 可选字段缺失即省略；顶层键集合以本表为**闭集**。**M5 例外（ISSUE-066，REV-031）**：`NodeWorker` 只增 `signal`/`exit_code`/`stderr_tail` 三个**可选**键（仅 `Some` 时输出，非 null）；后续任何新增仍须按本表登记或新增 `kind` 值并升 spec 版本，**不得**静默添加未列出的键。
- **`NodeWorker` 崩溃证据边界（ISSUE-066）**：只有 **supervisor 观察到 worker 进程退出**（非约定 exit code / 被信号杀死）时三键才可能有值；握手/协议/导入失败、**worker 自报 `NODE_WORKER_CRASH`（error 帧）**、spawn 失败均无进程退出证据 → 三键缺失。`stderr_tail` 取自 supervisor 已保留的**最后 8 KiB 中的末尾 1 KiB**（`STDERR_TAIL_BYTES=1024`），按 UTF-8 字符边界截断，**不脱敏**（排障证据，与 `PythonException.traceback` 同口径）；`error_code` 列仍取顶层 `code`，不因证据字段改变。
- **API 兼容备注**：`NodeError::NodeWorker` 公开 variant 增字段对仓外按字面量构造是 **source-breaking**；crate v0.1 已批准（REV-031 §7.3 #3），发布说明需备注。
- `error_code` 列 = 同对象的 `code` 值（冗余，便于 SQL 检索；00 §0.4/§8.2 取值域）。

### 6.2.6 统一事件信封（**全局 seq**）

```sql
CREATE TABLE IF NOT EXISTS events (
  seq         INTEGER PRIMARY KEY AUTOINCREMENT,   -- 全局单调（per DB 文件），允许空洞
  run_id      TEXT NOT NULL REFERENCES runs(run_id) ON DELETE CASCADE,
  kind        TEXT NOT NULL CHECK (kind IN
              ('RunStarted','Transition','GateResult','NodeTimedOut',
               'NodeAbandoned','Streaming','RunFinished')),
  severity    TEXT NOT NULL DEFAULT 'info' CHECK (severity IN ('info','warn','error')),
  at          TEXT NOT NULL,                       -- UTC RFC3339，毫秒精度
  instance_id TEXT,                                -- 可空（RunStarted/RunFinished 不携带 instance）
  node_id     TEXT,                                -- 可空（NodeTimedOut/NodeAbandoned 不携带 node）
  payload     TEXT NOT NULL                        -- JSON：TraceEvent payload 原文（00 §0.3 / 01 §1.5）
);

CREATE INDEX IF NOT EXISTS idx_events_run_seq  ON events(run_id, seq);
CREATE INDEX IF NOT EXISTS idx_events_kind     ON events(kind, seq);
```

## 6.3 事件模型与 `seq` 语义

**一句话结论**：`seq` 是**单 DB 文件内全局单调递增的整数**（允许空洞），是唯一因果排序依据；`at` 是墙钟，仅用于展示；run 内查询一律 `ORDER BY seq`。

### 6.3.1 事件分类与可丢性（I6 落地）

| `TraceEvent` | 可丢 | 写入方式 |
|---|---|---|
| `RunStarted` | ❌ | 无损（`send().await`） |
| `Transition` | ❌ | 无损 |
| `GateResult` | ❌ | 无损 |
| `NodeTimedOut` | ❌ | 无损 |
| `NodeAbandoned`（v2 不产生） | ❌ | 无损（兼容读取） |
| `RunFinished` | ❌ | 无损（恰好一次，I5） |
| `Streaming` | ✅ | 可丢（`try_send` + `streaming_dropped`） |

### 6.3.2 `seq` 规则

| 规则 | 规定 |
|---|---|
| 分配者 | **仅写线程**（`events.seq INTEGER PRIMARY KEY AUTOINCREMENT`；插入后 `last_insert_rowid()`） |
| 单调性 | 严格递增（per DB 文件）；并发 run 共用同一序列 |
| 空洞 | **允许**（事务回滚/`AUTOINCREMENT` 不回收）→ 消费者 MUST NOT 假设连续 |
| 排序 | run 内因果序 = `ORDER BY seq ASC`；**禁止**按 `at` 排序（墙钟可能逆序） |
| 明细关联 | `transitions/gate_results/streaming_events.seq` = 同事务信封 seq（`UNIQUE`，1:1） |
| 01 `TransitionRecord.seq` | 调度器侧填 `0`（占位）；**权威序 = `events.seq` 列**；读取/回放时以列覆盖 payload 内 `seq`（避免与 AUTOINCREMENT 分配时机冲突） |
| 跨进程 | 同机多进程共享 DB → SQLite 串行化写；seq 全局单调（各进程区间交错） |
| 进度列 | `runs.last_seq`/`event_count` 每批提交后同事务更新 |

### 6.3.3 `severity` 语义与推导

| 值 | 含义 | 产生场景（v1） |
|---|---|---|
| `info` | 正常生命周期 | `RunStarted`、正常迁移、`Streaming`（token/reasoning/progress）、`RunFinished{Completed/Cancelled}` |
| `warn` | 降级/告警但未失败 | `NodeAbandoned`、`GateResult{passed:false}`、`ToolCallEnd{ok:false}` |
| `error` | 导致 `Crashed`/`TimedOut` 或 run `Failed` | `NodeTimedOut`、迁移到 `Crashed`、`RunFinished{Failed}`、`GateResult` 带 error |

| 条件（写线程推导，固定） | severity |
|---|---|
| `kind='RunFinished' AND status='Failed'` | `error` |
| `kind='RunFinished' AND status IN ('Completed','Cancelled')` | `info` |
| `kind='Transition' AND to_status IN ('Crashed','TimedOut')` | `error` |
| `kind='Transition' AND to_status='Cancelled'` | `info` |
| `kind='GateResult' AND error IS NOT NULL` | `error` |
| `kind='GateResult' AND passed=0 AND error IS NULL` | `warn` |
| `kind='NodeTimedOut'` | `error` |
| `kind='NodeAbandoned'` | `warn` |
| `kind='Streaming' AND variant='tool_call_end' AND ok=0` | `warn` |
| 其余 | `info` |

> `severity` 是**存储层派生列**（不改变 00 的 `TraceEvent` 结构），供 CLI/SQL 告警筛选。

### 6.3.4 时间戳

| 列 | 语义 | 来源 |
|---|---|---|
| `events.at` | 事件产生时刻 | `RunStarted/NodeAbandoned/RunFinished` 用 payload `at`；`Transition/GateResult` 用 `record.ts`；**`NodeTimedOut` 用生产者（内核 watchdog）时间**（ISSUE-034：M2 实现取判定时刻，与落库时刻差 ≈ 入队延迟；不再取写线程收到时刻）；`Streaming` 用段内最后一条 delta 时刻 |
| `runs.started_at` / `finished_at` | run 生命周期 | 调度器 |
| `streaming_events.first_at` / `last_at` | 聚合窗口覆盖的真实增量区间 | 写线程聚合缓冲 |

> 所有时间戳 UTC、毫秒精度、`Z` 结尾（与 00 §0.1 一致）。

## 6.4 TraceEvent 写路径

**一句话结论**：两条有界通道（无损 `TraceEvent`、可丢 `Streaming`）→ **唯一写线程** → 每 256 行或 100 ms 提交事务；无损通道满时**等**（背压并计数），可丢通道满时**丢**（计数）。

### 6.4.1 拓扑

```
调度器事件循环 ──(send().await,  cap=TRACE_CHANNEL_CAP=8192)──┐
                                                               ├─→ 写线程（std::thread）
NodeContext.emit ──(try_send,     cap=STREAMING_CHANNEL_CAP=1024)┘      │
                                                                        ├─ 聚合 Streaming（§6.5）
                                                                        ├─ 收集 batch（≤256 行 / ≤100ms）
                                                                        ├─ BEGIN IMMEDIATE
                                                                        ├─ INSERT events → seq
                                                                        ├─ INSERT 明细 / UPSERT runs,instances
                                                                        └─ COMMIT（失败重试 3×50ms）
```

| 通道 | 容量常量 | 发送方式 | 满载行为 |
|---|---|---|---|
| 无损（6 类领域事件） | `TRACE_CHANNEL_CAP = 8192`（03 §3.12） | `send().await` | 生产者等待（背压），累计 `runs.trace_backpressure`（ms），> 1000ms 打 `warn` |
| 可丢（`Streaming`） | `STREAMING_CHANNEL_CAP = 1024`（00 §0.5） | `try_send` | 丢弃 + `streaming_dropped` 计数 |

> **M6 口径（REV-041，ISSUE-033 fixed；ISSUE-092 一并冻结）**：双通道拓扑已在 `zgraph-trace` **落地为实际实现**（M2 的单通道 `sync_channel(8192)` 为历史临时口径，已由 M6 拆回）：无损 `TRACE_CHANNEL_CAP = 8192`（`send` 阻塞，满载背压）+ 流式 `STREAMING_CHANNEL_CAP = 1024`（`try_send`，满/断开丢弃并累计 `streaming_dropped`），公开 `TraceHandle` API 不变。写线程用**发送序号有序合并**两条通道：**同一发送端**先发出的流式事件不会被其后的无损事件越过（「先流式后无损」顺序保持）；**跨发送端**只保证各通道 FIFO，**无全局全序**——不得据此推断不同生产者/不同通道之间存在全局事件序。`Flush`/`Shutdown`/恢复类控制消息到达时先排空流式通道再提交（barrier 覆盖两通道，关停不丢已入队事件）。`trace_backpressure` 指标仍无采集（`TraceSink` 为同步调用，恒 0——ISSUE-045，M6 未改）。
>
> **历史注记（不删除）**：M2 实现为单通道 `sync_channel(TRACE_CHANNEL_CAP = 8192)`（`send` 阻塞、`send_streaming` 用 `try_send` 丢弃计数），可丢/无损语义等价但容量统一为 8192；该临时口径已随 REV-041 撤销。

### 6.4.2 生产者规则（MUST）

| 规则 | 规定 |
|---|---|
| 事件循环不阻塞于 trace | 无损 `send().await` 正常情况下不等待（写线程 3.6 µs/条）；等待说明磁盘异常 → 记 `trace_backpressure` 并继续等（I6 优先于 tick 抖动，AC-07 以 <50ms 为界） |
| 节点侧只能 `try_send` | `NodeContext.emit` 永不加锁、永不 await、永不 panic（04 §4.2） |
| 顺序 | 先更新内存状态、再发事件；对应 `runs`/`instances` 变更与事件**同事务**提交（事件-快照不撕裂） |
| 时间戳 | 生产者侧取（`TraceEvent.at`/`record.ts`），写线程不补 |
| payload 大小 | 单条 payload ≤ 64 KiB（`TRACE_PAYLOAD_MAX_BYTES = 65536`）；超限 → `{"_truncated":true,"bytes":N}`；`Transition.error` 不截断。**M2 口径（ISSUE-035）**：`Transition` 超限时写线程返回 `TraceError::Serialize` 并使整批进入**不可恢复错误**（`take_error` 暴露，整批回滚）；M5 改为"仅该事件失败/映射领域错误"并补测试 |

### 6.4.3 写线程批处理算法（确定性）

```text
loop:
  batch = []
  deadline = now + TRACE_BATCH_INTERVAL_MS(100)
  while batch.len() < TRACE_BATCH_ROWS(256):
      timeout = deadline - now
      if timeout <= 0: break
      match poll_next_until(deadline):      # 见实现注记
          Ok(ev)   -> route(ev, batch)      # Streaming → 聚合缓冲；其余 → batch
          Timeout  -> break
          Disconnected -> flush_stream_buffers(); flush(batch); exit loop
  flush_stream_buffers() if batch not empty or deadline reached   # §6.5
  if batch.is_empty(): continue
  for attempt in 1..=DB_WRITE_RETRY:
      match write_tx(batch):                # BEGIN IMMEDIATE ... COMMIT
          Ok(seq_range)  -> update_metrics(seq_range); break
          Err(SQLITE_BUSY) if attempt < 3 -> sleep(50ms); continue
          Err(e) -> handle_fatal(e)         # §6.4.5
  if now - last_checkpoint > 5s: pragma(wal_checkpoint(PASSIVE))
  if now - last_heartbeat  > 5s: update runs.heartbeat_at for live runs (同事务)
```

> **实现注记**：契约级伪代码。实现可选 ① `tokio::sync::mpsc::Receiver::blocking_recv()` + `try_recv()` 轮转 + `Instant` 截止时间（推荐）；或 ② std `mpsc::sync_channel` 的 `recv_timeout`。语义相同：**先非阻塞收，再等到 deadline，达行数上限立即提交**。

| 常量 | 值 | 说明 |
|---|---|---|
| `TRACE_BATCH_ROWS` | `256` | 00 §0.5 |
| `TRACE_BATCH_INTERVAL_MS` | `100` | 00 §0.5（最大落库延迟；同时是流式聚合窗口） |
| `HEARTBEAT_INTERVAL_MS` | `5000` | 刷新 `runs.heartbeat_at`（§6.8） |
| `RECOVERY_HEARTBEAT_STALE_MS` | `60000` | 无法判活时的二次判据（§6.8.1） |

### 6.4.4 背压、丢弃与指标

| 指标 | 采集点 | 暴露方式 |
|---|---|---|
| `trace_rows_written` / `trace_batch_count` / `trace_write_ms_p95` | 写线程 | run 结束 stderr 摘要、`trace --stats` |
| `trace_backpressure`（累计等待 ms） | 无损发送方（调度器） | `runs.trace_backpressure` → `RunFinished.metrics`；> 1000ms 打 `warn` |
| `streaming_dropped` | `NodeContext.emit` 的 run 级原子计数器（04 §4.2） | `RunMetrics.streaming_dropped` → `runs.streaming_dropped`；**run 结束 stderr `warning: N streaming events dropped`** |
| `abandoned_tasks` | 调度器（D1） | `RunMetrics.abandoned_tasks` → `runs.abandoned_tasks`；**v2 恒 0**（保留字段兼容；AC-06 不再断言 ≥1） |
| `killed_workers` | 调度器/supervisor（D1/§8.2） | `RunMetrics.killed_workers` → `runs.killed_workers`；因超时/取消被 kill 的 worker 数（AC-06 断言 ≥1） |
| `trace_backpressure` | 无损发送方（调度器） | `runs.trace_backpressure` → `RunFinished.metrics`；M2 内核 sink 同步调用，恒 0（ISSUE-045） |

**丢弃可见性（AC 要求）**：`streaming_dropped > 0` 时 MUST 同时出现在 ① `zgraph run` 人类可读 stderr；② `--json` 结果；③ `trace --stats`。

### 6.4.5 写失败处理（fail-stop）

| 失败 | 处理 |
|---|---|
| `SQLITE_BUSY` | 重试 3 次 × 50 ms → 仍失败按不可恢复处理 |
| 磁盘满 / IO 错误 / DB 损坏 | **目标语义（不可恢复）**：① stderr `error[STORAGE_ERROR]`；② 通知调度器取消 run（内存态 `Failed`）；③ 尽力写一次终态；④ 退出码 **4**。**M6 已接线（REV-047，ISSUE-036 fixed）**：trace 写端不可恢复错误 → kernel 每轮在**控制命令处理之后、终态判定之前**轮询 `TraceSink::take_error`；非终态命中 → `fail_run_storage`（内存态 `Failed`、非终态实例→`Cancelled`、abort 在飞任务、**尽力**写 `RunFinished{Failed}`，`error = None`，`runs.error_code/error_message` 保持 NULL——§6.12.3 D3）；CLI 映射 `error[STORAGE_ERROR]` + **exit 4**。**边界**：真实 fatal 下写线程已停，「尽力写终态」可能被丢弃（DB 可能无 `RunFinished`、`runs` 停留 `Running`，仍按退出码 4 报错）；run 进入终态后不再轮询，错误留给 CLI `flush`/`close` 暴露（不静默成功）；`--json` 在该路径**不输出结果 JSON**（仅 stderr + exit 4，spec 无该 JSON 契约） |
| 迁移/版本错误 | 启动期直接退出码 **4**（不创建 run） |

> 理由：I6 要求 trace 因果完整；存储不可写还继续跑会让 trace 缺关键迁移而 run 显示成功。`STORAGE_ERROR` 属 **CLI/storage 命名空间**，不属于 00 §0.4 领域错误码，**不写入** `error_code` 列（见 §6.12.3 D3）。
>
> **故障注入验证（REV-047，跨模块主审 + 第二评审通过）**：kernel `tests/failstop.rs` 注入失败 → run `Failed`、`RunOutcome.error = STORAGE_ERROR`、慢节点前中止、`RunFinished.error = None`、终态后零 sink 调用（`trace_enabled=false` 不误失败）；CLI `tests/run.rs` 用 SQLite `BEFORE INSERT ON events` trigger 制造**确定性真实写失败**（不依赖 ENOSPC/只读 FS），断言 exit 4 + stderr `error[STORAGE_ERROR]` + 未出现 `Completed`。

### 6.4.6 关闭顺序（保证 I5/I6）

| 步 | 动作 |
|---|---|
| 1 | 调度器写 `RunFinished`（无损 send） |
| 2 | 关闭无损通道发送端 → 写线程断开后 flush 剩余 batch 与流式缓冲 |
| 3 | 写线程写最终 `runs` 终态 + `heartbeat_at`，`COMMIT` |
| 4 | `PRAGMA wal_checkpoint(TRUNCATE)` |
| 5 | 关闭连接；退出码按 §6.10.5 |

> `SHUTDOWN_GRACE_MS=5000` 内必须完成 1–4；超时强退（可能丢最后一批，stderr 告警）。

## 6.5 Streaming 聚合与落库策略（裁定）

**一句话结论**：**落"聚合后的分段"，不落逐 token**；聚合在**写线程**执行（单一聚合点 = 本分册），Harness 侧 1:1 emit（05 §5.8.3）；窗口 100ms / 单段 4096 字符 / 硬上限 16384 字节。

### 6.5.1 裁定与理由

| 选项 | 裁定 | 理由 |
|---|---|---|
| A. 逐 token 落库 | ❌ 否决 | 行数 ×10–100；`STREAMING_CHANNEL_CAP=1024` 易被淹没；回放可读性更差；正文可由分段拼接 |
| B. **写线程聚合后落段** | ✅ **采纳** | 与 03 §3.12「100ms 窗口合并相邻 `TokenDelta`/`ReasoningDelta` 后落库」一致；行数 ~10/s/实例；保留 `delta_count`/`first_at`/`last_at` |
| C. 只在实例结束落完整正文 | ❌ 否决 | 丧失流式可观测性；崩溃时正文全丢 |
| D. Harness 内先聚合再 emit | ❌ 否决 | 与 B 形成双窗口（段边界不可复现、两处常量漂移）；04 §4.2 的 `emit` 语义是 1:1 包 `TraceEvent::Streaming` |

### 6.5.2 聚合规则（写线程内，确定性）

| 规则 | 规定 |
|---|---|
| 聚合对象 | 仅 `TokenDelta`（kind=`token`）与 `ReasoningDelta`（kind=`reasoning`）；两类**各自独立缓冲**，不合并 |
| 不聚合 | `ToolCallStart`/`ToolCallEnd`/`Progress` 立即成段（1 事件 = 1 行），但它们到达前**先 flush 同实例的 token/reasoning 缓冲**（保持因果顺序） |
| 缓冲键 | `(run_id, instance_id, kind)` |
| flush 触发 | ① 批量提交边界（≤100ms，`STREAM_TOKEN_AGGREGATE_MS = TRACE_BATCH_INTERVAL_MS`）；② 缓冲 ≥ `STREAM_SEGMENT_MAX_CHARS=4096`（提前分段并继续新段）；③ 同实例出现非 delta 流式事件；④ 该实例进入终态（`Transition` → 终态）；⑤ 通道关闭/进程退出 |
| 段内容 | `text` = 窗口内按到达顺序的**无损拼接**（不丢字符）；`delta_count` = 合并数；`first_at/last_at` = 窗口首末 delta 的时刻 |
| 段序号 | `segment_index` 同 `(instance_id, kind)` 从 0 递增；写线程内存维护 `HashMap<key, next_index>`，进程启动/新实例首次出现时用 `SELECT MAX(segment_index)` 初始化 |
| 硬上限 | `STREAM_SEGMENT_MAX_BYTES = 16384`：UTF-8 字节超限 → 截断到码点边界 + `truncated=1`（防御异常大段） |
| 信封 | 每段 1 条 `events(kind='Streaming')` + 1 条 `streaming_events` 行（同一事务） |
| 可复现性 | 同一 fake-llm 脚本 + 相同 `chunk_chars` → 段边界确定（AC-08 回归断言） |
| 丢弃 | 未到达写线程的 delta 不可恢复；`streaming_dropped` 记录总量；段文本只含已到达部分（不伪造） |

### 6.5.3 与 `events` 的关系

| 字段 | 取值 |
|---|---|
| `events.kind` | `'Streaming'` |
| `events.payload` | 变体最小 JSON（如 `{"variant":"token","chars":512,"delta_count":37}`），**不重复存正文** |
| `events.severity` | token/reasoning/progress → `info`；tool_call_end 且 `ok=0` → `warn` |
| `events.at` | 段内最后一条 delta 的时刻（`= last_at`） |
| `events.instance_id` | 携带；`events.node_id` 由写线程按 `instances` 快照回填 |

### 6.5.4 容量估算（推断，待 AC-01 校准）

| run 形态 | 流式行数 | 占库空间（估算） |
|---|---|---|
| 5 节点 + 1 Agent（无工具，2000 字符输出） | ~8–15 | ~10–20 KB |
| 5 节点 + 1 Agent（3 轮工具，8000 字符输出） | ~40–60 | ~40–80 KB |
| 全量单 run（迁移 + 门控 + 流式 + 实例） | — | ~40–120 KB |

> 10 万 run 约 4–12 GB；v1 保留全部、不自动清理（§6.9）。

## 6.6 连接、并发与多进程

**一句话结论**：写连接独占单写线程；读连接任意多、走 WAL 快照；同机多进程允许但**不支持跨机/网络盘**。

| 场景 | 连接 | 规则 |
|---|---|---|
| `zgraph run` | 1 写连接（写线程持有） | 写线程用 `BEGIN IMMEDIATE` 批量提交 |
| `zgraph trace` | 只读连接（`?mode=ro`） | 只读 + `busy_timeout`；**不**触发迁移与恢复 |
| 同进程多 run（库 API） | 共享 1 写线程 + 1 写连接 | 事件按到达顺序串行提交；各 run 行独立更新 |
| 同机多进程 | 各自写连接 | WAL + `busy_timeout=5000`；写冲突由 SQLite 串行化；`seq` 全局单调 |
| 跨机 / NFS / 网盘 | ❌ 不支持 | WAL 与文件锁不可靠；文档明确禁止 |
| 测试库 | 临时文件（`--db $TMPDIR/...`）或 `:memory:`（仅库 API） | §6.9 |

**只读模式**：`trace` 在 DB 不存在时**不得创建空库** → 退出码 4 + `error[STORAGE_ERROR]: database not found`。

## 6.7 Schema 版本与迁移

**一句话结论**：forward-only 迁移；版本存 `PRAGMA user_version` + `schema_migrations`；版本超前则拒绝；迁移前逐版本 `VACUUM INTO` 备份。**M6 起 schema 版本 = 3**（REV-049）。

| 步骤 | 动作 | 失败处理 |
|---|---|---|
| 1 | 打开 DB（不存在则创建） | IO 错误 → 退出码 4 |
| 2 | `PRAGMA user_version` | — |
| 3 | `user_version == 0` → 全新库：**单事务**执行当前版本 DDL + 写 `schema_migrations` **1/2/3** 三行基线 + `PRAGMA user_version = 3`（不产生备份） | 回滚 + 退出码 4 |
| 4 | `0 < user_version < 3` → **逐版本循环迁移**（v1→v2→v3）：每步迁移前 `VACUUM INTO '<db>.bak.v{old}-{ts}'`（并回写备份 `user_version=old`、校验）；**单版本单事务**；成功后插入对应 `schema_migrations` 行并更新 `user_version` | 失败 → 删 `-wal`/`-shm` → 用备份覆盖恢复 → 退出码 4 |
| 5 | `user_version == 3` → 就绪 | — |
| 6 | `user_version > 3` → **拒绝**：`error[STORE_SCHEMA_TOO_NEW]: db version=N, supported=3` | 退出码 4 |
| 7 | 只读连接（`trace`/`replay`）版本 < 3 → **拒绝且不迁移**：`unsupported schema version=N, expected 3` | 退出码 4 |

| 规则 | 规定 |
|---|---|
| 迁移粒度 | 每版本一个事务；禁止迁移中做业务逻辑 |
| 幂等 | 新库用 `CREATE TABLE IF NOT EXISTS`；旧库靠 `user_version` 保证只执行一次 |
| 破坏性变更 | 只允许新增表/列/索引；删改列必须新建表 + 拷贝 + 改名（SQLite 12 步法） |
| 备份保留 | **M6 口径（REV-049）**：`.bak.v{old}-{ts}` **不自动清理**（避免误删唯一快照）；原「保留最近 3 份」由**运维动作**执行，程序不做删除 |
| 测试 | 新库 → `user_version=3` + `schema_migrations` 1/2/3 各一条且无备份；v1→v3 / v2→v3 原地升级、留备份且原行保留；迁移失败注入 → 备份恢复为旧版本（`user_version` 与列均回退）；只读拒绝 v1/v2 与新版本 |

> **M6 实现要点（REV-049，ISSUE-087）**：`migrate_step` 的 v1→v2 建表/补 `seed` 等 v2 列，v2→v3 只补 `runs.global_vars_json`；备份文件同时写回 `user_version`（`VACUUM INTO` 不保证保留 DB 头版本，恢复回旧版本时必需）；恢复前先删 `-wal`/`-shm`，避免 WAL 回放污染恢复后的旧库。未知版本号（非 1/2）不静默跳过 → 存储错误。

## 6.8 故障与恢复（v1 裁定）

**一句话结论**：进程崩溃后**不改枚举、不合成事件、不改写历史**；只把"无活动进程"的 `Running`/`Paused` run 标定为 `Failed + interrupted=1`，`trace` 显式提示截断。

### 6.8.1 标定规则（`zgraph run` 启动时自动执行）

| 步 | 动作 |
|---|---|
| 1 | `SELECT run_id, status, owner_pid, owner_host, heartbeat_at FROM runs WHERE status IN ('Running','Paused')` |
| 2 | 判活（顺序固定）：① `owner_host == current_host` 且 `pid_alive(owner_pid)` → **跳过**（同机合法并发）；② 跨机 → `heartbeat_at` 距今 > `RECOVERY_HEARTBEAT_STALE_MS=60000` 才判死，否则跳过并告警；③ 同机但 pid 不存在 → 判死 |
| 3 | 判死的 run：`UPDATE runs SET status='Failed', interrupted=1, recovered_at=now, error_message='run interrupted: owner process exited' WHERE run_id=? AND status IN ('Running','Paused')`；**`error_code` 保持 NULL**（中断不是 00 §0.4 的任何错误码，S6） |
| 4 | **不**修改 `instances` 行；**不**写 `RunFinished`；**不**写 `Transition` |
| 5 | stderr：`warning: run <id> marked interrupted (was Running, pid 12345 gone)`；`--json` 时进入 `recovered[]` |

> `pid_alive` 用 `kill(pid,0)` 语义；pid 复用是残余风险（`heartbeat_at` 二次佐证）。
>
> **标定入口（N-04；M5 实现口径，REV-034 + REV-030，已合并）**：v2 无 `RunManager`，标定 = **trace 两段原语 + CLI 调用方**：
> ① `TraceWriter::interrupted_candidates()` 返回 `Running`/`Paused` 候选（`run_id/status/owner_pid/owner_host/heartbeat_at`，稳定排序）；
> ② 判活**由 CLI**（`crates/zgraph-cli/src/recovery.rs`）按上表步 2 顺序执行：同机（`owner_host` == 本机，或 DB 未记录 host）且 `kill(pid,0)` 存活 → 跳过；跨机 → `heartbeat_at` 距今 > `RECOVERY_HEARTBEAT_STALE_MS=60000` 才判死，否则跳过；同机且 pid 缺失/不存在 → 判死；非 Unix 无 `kill(pid,0)`，保守视为存活、**不**自动标定（避免误杀并发 run）；
> ③ `TraceWriter::mark_interrupted(&[run_id], now)` 在写线程**单事务**内条件 `UPDATE`，返回 `RecoveredRun{run_id, previous_status, recovered_at}`；`error_code`/`finished_at` 保持 NULL、不改 `instances`、不合成 `RunFinished`/`Transition`（§6.8.2）；
> ④ `zgraph run` 在打开 DB/迁移后、编译图/建 run 前调用，stderr 输出 `warning: run <id> marked interrupted (was Running, pid N gone)`；`--json.recovered[]` 元素为 `{run_id, previous_status, recovered_at}`；`trace` 永远只读、不标定。
>
> **残余风险与台账**：**ISSUE-084 已 fixed**（核心实现 + kill -9 自动化 e2e，REV-034/030/032）；下列多机/多用户边界**转 ISSUE-088（M6，open）**：跨机 heartbeat 未陈旧时「跳过并告警」未实现（`--json.warnings` 恒空，仅被标定 run 有 stderr）；`current_host` 仅取 `HOSTNAME`/`COMPUTERNAME`，缺省 `unknown` 时跨机会被当同机而走本地 pid 判活；`pid_alive` 对 EPERM（进程存在但无权限）视为不存在；`trace` 的 pid 提示未校验 `owner_host`。实现已完成并有 kill -9 自动化 e2e（REV-032）；上述边界留 M6 加固（不阻塞 ISSUE-084 fixed）。

### 6.8.2 为什么是"Failed + interrupted"（D1）

| 方案 | 否决/采纳理由 |
|---|---|
| 新增 `RunStatus::Interrupted` | 需改 00 §0.3 枚举（01/03/07/CLI 全部连锁）；v1 用 `interrupted` 列等价表达 |
| 把在飞实例改成 `Crashed` | 会**伪造**一次不存在的状态迁移（trace 中状态只由 `Transition` 改），违反 I6 因果完整 |
| 合成一条 `RunFinished` | 违背 I5「恰好一次」；回放器会把"事后补发"误判为真实时序 |
| **只标 runs、保留 instances 原样** | ✅ 采纳：事实（最后快照）与标定（run 中断）分离；`trace` 显式提示 |

### 6.8.3 `trace` 对中断 run 的输出

| 情况 | 输出 | 退出码 |
|---|---|---|
| `interrupted=1` 且无 `RunFinished` | 末尾 `!! trace truncated: run interrupted at <recovered_at> (no RunFinished)` | **1** |
| `status='Running'` 且 pid 仍活 | `run still in progress (pid N)` | 0 |
| 有 `RunFinished` | 正常回放 | 0（Completed/Cancelled）/ 1（Failed） |

> **M5 口径（ISSUE-048，REV-034 + REV-030 + REV-032）**：`RunRow` 已携带 `owner_pid`/`owner_host`/`heartbeat_at`（REV-034）；`zgraph trace` 对 `Running`/`Paused` 且 `owner_pid` 存活者向 **stderr** 输出 `run still in progress (pid N)`（stdout 保持纯数据/NDJSON、exit 0）；interrupted run 的截断提示与 exit 1 已实现并有 kill -9 e2e（REV-032）。**残余风险（REV-030 #5）**：该提示未校验 `owner_host`，跨机 run 的 pid 与本机同号进程可能误报（只影响 stderr 诊断）。

### 6.8.4 不实现断点续跑（v1.1）

| 原因 | 说明 |
|---|---|
| 在飞任务不可重建 | LLM 流式中断无法"续上同一响应"；Python 节点/工具可能已有外部副作用 |
| 幂等边界缺失 | v1 无工具幂等键、无外部效果去重 |
| 双事实源风险 | resume 需 checkpoint（M-06），与决策记录 §2.2「不做断点恢复」冲突 |
| 替代 | `graphs.dsl_json` + `events` 支持**只读回放**；重跑 = 新 run（新 `run_id`，`attempt` 不跨 run） |

> v1.1 恢复需要：① 每实例 checkpoint（buffer + 消息序列 + iteration）；② 工具幂等键；③ 事件溯源重放器；届时新增 `checkpoints` 表（v1 **不**预埋空表）。

### 6.8.5 故障对照

| 故障 | 处理 |
|---|---|
| 进程崩溃 / kill -9 | §6.8.1 标定（下次 `run` 启动时） |
| 掉电（`synchronous=NORMAL`） | 最后若干已提交事务可能丢；DB 一致（WAL）；run 会被标定为 interrupted |
| DB 损坏 | 打开/读写报错 → 退出码 4；不自动修复（手工 `sqlite3 .recover`） |
| `-wal`/`-shm` 残留 | 下次打开自动恢复；`trace` 只读模式先恢复 WAL 再读 |

### 6.10.3 `zgraph run`

```
zgraph run <graph.json> --inputs <json|@file>
        [--user-id <id>] [--db <path>]
        [--assets-dir <dir>] [--tools-dir <dir>]
        [--fake-llm[=<script.json>]] | [--real]
        [--record=none|hash|full]
        [--stream] [--json]
```

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `<graph.json>` | ✅ | — | DSL 文件 |
| `--inputs` | ✅ | — | JSON 字符串或 `@file`；形状见下 |
| `--python <exe>` | ❌ | `--python` > env `PYO3_PYTHON` > env `ZGRAPH_PYTHON`（仅测试/CI 覆盖）> `python3` | worker 子进程解释器可执行文件（每次 spawn 使用；04 §4.3.6，REV-028 收敛优先级） |
| `--python-path <dir>` | ❌ | 空 | 可重复；按序注入模块搜索路径（叠加 `PYTHONPATH`），首次 import 前一次性生效 |
| `--user-id` | ❌ | `"local"` | `runs.user_id`；`GateContext.user_id` |
| `--db` | ❌ | `.zgraph/trace.db`（env `ZGRAPH_DB`） | §6.9；`:memory:` 结果直接取 outcome、`event_count` 恒 0、`trace` 读不到（§6.9.1） |
| `--assets-dir` / `--tools-dir` | ❌ | `.` / `<assets-dir>/tools` | 02 §2.6.3 / 05 §5.2.1 |
| `--fake-llm[=<script>]` | ❌ | — | FakeLlmProvider（05 §5.3.4）：**裸 flag = CLI 内置默认脚本**（内容不保证确定）；`=<path>` 指定脚本（07 §7.1/AC-01；确定性验收必须显式脚本） |
| `--real` | ❌ | — | 真实 provider（需 `*_API_KEY`；仅 AC-08 手动；与 `--fake-llm` 互斥） |
| `--record <mode>` | ❌ | `hash` | L2 记录模式 `none`/`hash`/`full`（D9）：透传内核并写 `runs.record_mode`；L2 重放要求运行期 `full`（§6.2.13、DR-002 §3） |
| `--stream` | ❌ | 关 | 把 `TokenDelta`/`ReasoningDelta` 文本实时打到 **stderr**（不改变 trace） |
| `--json` | ❌ | 关 | stdout 输出最终结果 JSON（§6.10.6） |

**`--inputs` 形状**：

| 图形态 | 允许写法 |
|---|---|
| 任意 | 嵌套（**总是允许**）：`{ "<node_id>": { "<port>": value } }`，如 `{"input_parser":{"user_message":"我要退款"}}`（AC-01） |
| 恰好 1 个 entry | 简写：`{ "<port>": value }`（自动归属该 entry 节点） |
| 非法 | 非 entry 节点 / 未声明端口 / required 端口缺失 → `RUN_ENTRY_INVALID` / `RUN_ENTRY_INPUT_MISSING`（退出码 **3**，**不产生 run**） |

| 项 | 规定 |
|---|---|
| 启动顺序 | 打开 DB → 迁移检查 → 中止标定（§6.8.1：trace 候选 + CLI 判活/`mark_interrupted`，REV-030 已实现）→ 编译图（失败退出 2，不创建 run）→ 建 run 行 + `RunStarted` |
| 运行中 | human 模式 stderr 每行一条生命周期事件（§6.10.3 示例）；`--stream` 追加流式文本 |
| 结束 | human 模式 stdout 输出 `run_output` JSON；`--json` 输出 §6.10.6 |
| SIGINT | 置取消标志 → 等 `SHUTDOWN_GRACE_MS` → 写 `RunFinished{Cancelled}` → 退出码 **130** |
| 存储不可写 | fail-stop（§6.4.5），退出码 4 |

> **M6 口径（REV-050，ISSUE-085 fixed）**：human 模式生命周期行**实时**输出（run 运行中逐行写 stderr，不再等 run 结束回读 trace）——实现为 bridge 的**只读旁路** `LifecycleObserver`（映射后、`send` 前回调一次，**不写库、不改变落库 events 行数与顺序**），CLI 在 `created` 行之后启动独立打印线程；run 结束用哨兵 + join 收尾，`:memory:` 同样走旁路。**token/reasoning 增量不逐块成行**（trace 写线程按 100 ms/4096 聚合为段，旁路拿不到段边界），原文由 `--stream` 提供。**`[seq N]` 是 CLI 侧事件序号**（1 起、只对产生 `events` 行的事件递增）：单 run 新库且无 token 段时与 trace `events.seq` 一致；含流式增量时可能小于 trace 的聚合段编号。`--json` **无**生命周期行、`-q` 仍抑制；`--stream` 原文与生命周期行共用 stderr，可能交错（可接受）。

### 6.10.4 `zgraph trace`


| 参数 | 默认 | 说明 |
|---|---|---|
| `<run_id>` | 必填 | 不存在 → 退出码 **4**（`error[STORAGE_ERROR]: run not found`） |

### 6.10.5 退出码（权威表）

| 码 | 含义 | validate | run | replay | trace |
|---|---|---|---|---|---|
| `0` | 成功 | 合法（02 §2.7.4） | `Completed` | `--mode=outputs` 重放输出与原始一致；`--mode=events` 完整回放 | 完整回放且 run 成功/Cancelled |
| `1` | 其他/run 未成功 | IO/内部错误（02） | `Failed`；程序化取消 | `REPLAY_OUTPUT_MISMATCH`；events 模式 run `Failed`/interrupted | run `Failed` 或 interrupted |
| `2` | 图/资产错误或用法错误 | `DSL_*`（02 §2.7.4） | 图/资产加载失败（**不创建 run**）；用法错误 | 用法错误 | 用法错误 |
| `3` | 启动参数非法（**不产生 run**）；replay 记录类错误（CLI 命名空间，**不写** `runs.error_code`） | — | `RUN_ENTRY_INVALID` / `RUN_ENTRY_INPUT_MISSING` / `RUN_TOO_MANY` | `REPLAY_RECORD_MISSING`（缺 `--record=full`）/ `REPLAY_RUN_NOT_COMPLETED`（原始 run 非 Completed）/ `REPLAY_RECORD_CORRUPT`（记录损坏：hash 复核失败 / 重复记录 / 缺 `output_json` / `entry_inputs` 非法） | — |

| `130` | SIGINT（128+2） | — | 用户 Ctrl-C（run 标 `Cancelled`） | — | — |

**取消细分**：用户 Ctrl-C → run `Cancelled` + **130**；程序化取消（库 API）→ `Cancelled` + **1**；存储故障取消 → `Failed`（若可写）+ **4**。

>
> **M6 统一口径（REV-043，ISSUE-059 fixed）**：`validate` 的 M1 临时口径 **3 已删除**——用法错误 → **2**、IO/内部 → **1**、panic → **70**、合法 → **0**，与上表逐行一致；`trace` 维持用法 2、存储 4。e2e 已补真二进制回归（`validate_exit_codes_match_spec`：合法 0 / 坏图 2 / 文件不可读 1）。

|---|---|
| `--mode=events`（默认，L1） | 直接委托 `zgraph trace` 的只读回放实现与输出格式（human 与 `--json` NDJSON 均**逐字节一致**）；**不重跑、不写库**；run `Failed`/interrupted 沿用 trace 退出码（0/1/2/4） |
| `--mode=outputs`（L2）预检 | 只读打开 DB；`runs.record_mode` 必须为 `full`（否则 `REPLAY_RECORD_MISSING`）→ run 必须 `Completed`（否则 `REPLAY_RUN_NOT_COMPLETED`）→ 逐条 `recorded_outputs`：`output_json` 必须存在、`blake3(canonical_json(output))` 复核等于 `output_hash`、`(node_id, attempt)` 不得重复（否则 `REPLAY_RECORD_CORRUPT`）→ 已执行且 `Completed` 的非内置实例（`python_node`/`agent_call`）必须都存在对应 `(node_id, attempt)` 记录（否则 `REPLAY_RECORD_MISSING`） |
| L2 重跑 | 从 `runs.graph_hash` JOIN `graphs.dsl_json` 载入图、由 `entry_inputs`/`user_id`/`seed`/**`global_vars`** 重建 `RunSpec`（M6 起从 `runs.global_vars_json` 还原：object → 逐键重建；v3 前历史 run 为 NULL → 空 map + stderr 告警；非 object → `REPLAY_RECORD_CORRUPT`）；`RecordedExecutor` 按 `(node_id, attempt)` 直接返回记录 `output_json`，**不启动 worker/LLM**；trace 用 `MemoryTraceSink`（不落库）；`start`/`end` 为内核内置执行、不查记录 |
| L2 判定 | 比较重跑 `status`/`error` 与 output：仅当重跑 `Completed`、`error=None` 且 output == 原始 `runs.output_json` → `matched=true`、exit 0；否则 `REPLAY_OUTPUT_MISMATCH`、exit 1（stderr 给差异摘要，`--json` 带 `error`）。原始 Completed run 的 `error_code` 按约定为 NULL（比较不单独读该列；REV-030 #9 防御性 Nit） |
| 不写 | **不创建新 run、不修改原 trace**（所有 DB 访问走 `TraceReader::open_readonly`；REV-030/032 以 DB 主文件 SHA + marker 日志 + `ZGRAPH_PYTHON=/nonexistent` 仍成功实测验证）；不写 `runs.error_code`；`llm_calls` 仅审计、**不参与重放** |
| 错误/退出码 | 记录缺失/不完整 → `REPLAY_RECORD_MISSING`；原始 run 非 Completed → `REPLAY_RUN_NOT_COMPLETED`；记录 hash 不符/重复/缺 `output_json`/`entry_inputs` 非法 → `REPLAY_RECORD_CORRUPT`（均 **exit 3**）；输出不一致 → `REPLAY_OUTPUT_MISMATCH`（**exit 1**）；run/图不存在、DB 错误 → exit 4；用法 → exit 2 |
| 已知边界 | **M6 已修（REV-049，ISSUE-087 fixed）**：`global_vars` 已落库并在重放中还原（见上表）；`entry_inputs` 非 object/记录损坏仍按 `REPLAY_RECORD_CORRUPT`；v2 库只读拒绝（`unsupported schema version=2`，exit 4，不迁移）。残余：L3 外部副作用不重放；`--dry-run` 不实现（architecture §5.1/§5.3） |

> **e2e 验收（REV-032，`tests/e2e/cli_replay.rs` 9 用例）**：L2 成功（`matched=true`、`original_output==replayed_output`、runs 计数不变、DB 主文件 SHA 不变、marker 日志不变、`ZGRAPH_PYTHON=/nonexistent` 仍成功 = 不启动 worker 的可判定证据）；L1 与 `trace --json` 逐字节一致；`hash` 模式/删一条记录 → `REPLAY_RECORD_MISSING` exit 3；篡改 `output_hash` → `REPLAY_RECORD_CORRUPT` exit 3；篡改 `runs.output_json` → `REPLAY_OUTPUT_MISMATCH` exit 1；非 `Completed` → `REPLAY_RUN_NOT_COMPLETED` exit 3。e2e 包 **37 passed / 0 failed / 1 ignored**。
>
> **M6 增量（REV-049，`tests/e2e/cli_replay.rs` + `zgraph-cli` 单测）**：CLI `run` 记录 `global_vars = {}`；`replay --mode=outputs` 读回已记录值并真正进入重跑环境（`ctx.get_var` 复现输出）；v3 前历史 run（NULL）→ 空 map + stderr 告警；非 object → `REPLAY_RECORD_CORRUPT` exit 3；v2 库只读拒绝 → exit 4。replay 全程只读、不迁移。

## 6.11 指标与自检

**一句话结论**：v1 不接外部 metrics；指标通过 ① run 结束摘要、② `trace --stats`、③ SQL 三处暴露；AC-03/06/08 依赖 ②③。

### 6.11.1 run 结束摘要（stderr / `--json`）

| 指标 | 来源 |
|---|---|
| `duration_ms` | `finished_at - started_at` |
| `event_count` | `runs.event_count` |
| `streaming_dropped` | `runs.streaming_dropped`（`RunMetrics`） |
| `abandoned_tasks` | `runs.abandoned_tasks`（v2 恒 0；保留字段兼容） |

| `trace_backpressure` | `runs.trace_backpressure` |
| `trace_write_ms_p95` | 写线程进程内统计（不落库） |
| `llm_calls` / `tool_calls` | 由 `streaming_events`（progress 数 / tool_call_end 数）聚合 |

### 6.11.2 `trace --stats` 输出

```text
run 0192f0c4-... status=Completed duration=1842ms
events 18  (RunStarted 1, Transition 12, GateResult 2, Streaming 2, RunFinished 1)
```

### 6.11.3 完整性自检（AC-03 附带 + 测试）

| 检查 | 规则 |
|---|---|
| `seq` 单调 | 查询结果 seq 严格递增（允许空洞） |
| I5 | 每个 run 的 `RunFinished` 至多 1 条；非 interrupted 的终态 run **恰好** 1 条 |

| dropped 归零 | AC-01/AC-02 断言 `streaming_dropped == 0` |
