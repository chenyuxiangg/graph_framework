## 0.1 读法与约定

- **MUST / MUST NOT / SHOULD / MAY**：分别表示强制、禁止、建议、可选。实现与测试以此判定合规。
- 本规格中所有 Rust 片段是**契约级伪代码**：字段名、枚举、语义是强制的；所有权/生命周期写法是建议（实现可按第 03 分册的所有权模型调整），但**不得改变语义**。
- 所有时间戳为 UTC RFC3339；时间量单位为毫秒（`_ms` 后缀）。
- `Value` = `serde_json::Value`。
- **DSL schema 版本保持 `"version": "1.0"` 不变**（新增字段均为可选/保留字，向后兼容）；本文档自身版本为 v1.2。
- **语义收紧说明**：符号命名从 v1.1 的短名收紧为全限定 `module.function`（02 §2.5）；这是语义收紧而非字段变更，v1 不兼容旧短名。

## 0.2 ID 与类型别名

| 别名 | 底层 | 生成规则 | 说明 |
|---|---|---|---|
| `NodeId` | `String` | DSL 中声明 | 图内唯一 |
| `SubgraphId` | `String` | DSL 中声明 | 子图内唯一 |
| `PortName` | `String` | DSL 中声明 | 节点内唯一 |
| `EdgeIdx` | `usize` | 编译期按 `edges` 数组顺序 | 边的稳定**数值**标识（原 `EdgeIndex = usize` 别名，ISSUE-043 裁定） |
| `EdgeIndex` | 结构体（见 01 §1.1.2） | 编译期构造 | 边索引结构体（`outgoing`/`incoming`/`incoming_by_node`），与 `EdgeIdx` 分工 |
| `RunId` | `String` | UUIDv7 | 全局唯一、时间有序 |
| `InstanceId` | `String` | UUIDv7 | 全局唯一；实例创建时生成 |
| `Attempt` | `u32` | 从 0 开始 | 同节点重建实例时 +1（仅自环/重试） |
| `ItemIndex` | `u32` | 展开内元素下标 | **W4a**：`0..N-1`；非 foreach region 节点恒 0；实例定位键 `(NodeId, ItemIndex)` 的组成部分 |
| `ExpansionId` | `String` | UUIDv7 | **W4a**：一次 `foreach` 展开事实的标识（trace `foreach_expansions.expansion_id`） |
| `GraphHash` | `String` | `blake3` 规范化 JSON，取前 16 hex | run 与图定义绑定 |

> 实例唯一性由 `InstanceId` 保证；`(NodeId, Attempt)` 仅用于**定位同一节点的当前实例**（v1 同一节点同时最多一个活跃实例，见 01 分册 §1.4）。
>
> **命名裁定（ISSUE-043，M2 回写）**：`EdgeIndex` 与 `EdgeIdx` 是**两个不同类型**——`EdgeIndex` 是边索引**结构体**（01 §1.1.2），`EdgeIdx` 是 `usize` **数值别名**（数组下标）。凡"边的数值标识"一律写 `EdgeIdx`；凡"出/入边索引表"一律写 `EdgeIndex`。Rust 不允许二者同名别名共存，实现（`crates/zgraph-kernel/src/types.rs`）即按此落地。

## 0.3 枚举（权威定义）

```rust
/// DSL 节点类型
pub enum NodeType { Start, End, PythonNode, AgentCall, Subgraph }   // Subgraph: v1 运行时不支持

/// 边级「门控失败策略」（DSL `on_gate_false`；W2a0，02 §2.2.2 / 01 §1.1.1）
pub enum OnGateFalse {
    Settle,   // Default：gate=false → 结算入边 + Skipped 级联（v0.1.0 语义）
    Defer,    // gate=false → 只记 DeferredReceipt，不结算、不 Skipped（W2a0；opt-in）
}

/// 人工决策值（W3a0；`builtin.human` 节点 output 的 decision 字段 / human_decisions.decision）
pub enum HumanDecision {
    Approved,   // 批准（节点 Completed；后续路由交给图）
    Rejected,   // 驳回（同样是正常 Completed；不隐式 Failed；路由交给图）
}

/// 实例状态（v0.2/W3a 全部可产生的状态）
pub enum InstanceStatus {
    Pending,       // 已创建，等待输入
    Ready,         // 输入就绪，等待调度
    Running,       // 已派发执行
    WaitingHuman,  // W3a0：输入就绪、等待人工决策（非终态、不执行、不占 worker；01 §1.2.4 / 03 §3.4.5）
    Completed,     // 成功（终态）
    Crashed,       // 失败（终态）
    TimedOut,      // 超时（终态；v2 = kill，D1；不再有 stop-waiting/NodeAbandoned）
    Cancelled,     // 被取消（终态）
    Skipped,       // 入边全部被门控拦截，永不执行（终态）
}

/// run 状态
pub enum RunStatus {
    Running,
    Paused,
    Completed,  // 终态：静默结束且未失败
    Failed,     // 终态：冷峻失败（任一 Crashed/TimedOut/框架错误）
    Cancelled,  // 终态：用户取消
}

/// 节点执行错误（进入 InstanceRecord.error）
// NodeError.code 取值域（BusinessError.code）：NODE_RETURN_NOT_DICT / NODE_RETURN_NOT_JSON / BIZ_*（业务自定义）。
// 框架错误用 Internal/Config；Harness 配置失败用 Harness{kind: ConfigLoad}，NodeError::Config 仅用于非 Harness 资产加载。
pub enum NodeError {
    BusinessError { code: String, message: String },        // 节点主动抛出
    PythonException { message: String, traceback: String }, // Python 未捕获异常
    Timeout { elapsed_ms: u64 },                            // 实例级超时
    Cancelled,                                              // 协作取消
    Harness { kind: HarnessErrorKind, detail: Value },      // Agent Harness 错误
    Config { message: String },                             // 配置/资产加载失败
    Internal { message: String },                           // 框架不变量违反（fail-fast）
    NodeWorker { kind: WorkerErrorKind },                   // worker 子进程错误（D10；v2 新增）
    FanoutExceeded { limit: u32, actual: u32 },             // W2b：单次激活放行边数超 max_fanout（防御层）→ NODE_FANOUT_EXCEEDED
}

// NodeError::code() 对 FanoutExceeded 返回 NODE_FANOUT_EXCEEDED（00 §0.4 运行期域）；
// Display 稳定为「node fan-out {actual} exceeded max_fanout ({limit})」。

/// worker 子进程错误分类（architecture-v2 §8.2；NodeError::NodeWorker 的载荷）
pub enum WorkerErrorKind {
    Handshake,  // hello 超时 / 协议版本不匹配 / 缺 sdk_version → NODE_WORKER_HANDSHAKE
    Protocol,   // 非法帧 / exit 0 无 result / result 后不退出 / 半行帧 / 超 8 MiB → NODE_WORKER_PROTOCOL
    Import,     // worker 启动时 module/function 导入失败或签名不符（D7）→ NODE_WORKER_IMPORT
    Crash,      // 被信号杀死 / 非约定 exit code → NODE_WORKER_CRASH
}

/// Harness 错误分类（映射见 05 分册 §5.7）
pub enum HarnessErrorKind {
    ConfigLoad,
    UnknownTool,
    MaxIterations,
    LlmError,
    LlmTimeout,
    ToolError,          // 仅喂回 LLM，不终止
    MemoryDegraded,     // 降级告警，不终止
    ContextOverflow,    // M4 追加（方案 A，D18）：预算裁剪后仍溢出 → HARNESS_CONTEXT_OVERFLOW，见 05 §5.13
    // v0.3 追加（REV-096 Lead 裁决 A；H6 唯一例外，3 个）：
    SkillInvalid,       // skills 存在但格式非法 → HARNESS_SKILL_INVALID（缺失引用仍 HARNESS_CONFIG_LOAD{skill_not_found}）
    Mcp,                // MCP 配置/allow/lifecycle/崩溃 → HARNESS_MCP_ERROR（detail.reason；工具调用失败仍 TOOL_ERROR）
    Plugin,             // 外部 harness spawn/握手/协议/崩溃/超时 → HARNESS_PLUGIN_ERROR（detail.reason；超时 reason=timeout）
}
> **v0.3 as-built（2026-11-02，REV-101）**：`SkillInvalid`/`Mcp`/`Plugin` 三个 variant 已由 V2/V3/V4 落地（`CODE_HARNESS_SKILL_INVALID`/`CODE_HARNESS_MCP_ERROR`/`CODE_HARNESS_PLUGIN_ERROR`；append-only，既有 8 值/码不变）；对应 C1–C5 设计裁决与 REV-097/098/099。

/// 流式事件（节点 ctx.emit 产生；只进 trace，不参与数据通道）
pub enum StreamingEvent {
    TokenDelta { text: String },
    ReasoningDelta { text: String },
    ToolCallStart { call_id: String, tool_name: String, args_summary: Value },
    ToolCallEnd { call_id: String, tool_name: String, ok: bool, result_summary: Option<Value> },  // M4：可空
    Progress { percent: u8, message: String },
}
```

## 0.4 错误码总表

错误码是**对外契约**：CLI 输出、trace、测试断言都依赖它。格式 `域_类别[_细节]`。

### DSL 域（图加载期；Loader 返回，不产生 run）

| 错误码 | 触发条件 | 规格来源 |
|---|---|---|
| `DSL_PARSE_ERROR` | 非法 JSON / 类型不符 | 02 §2.4 |
| `DSL_MISSING_FIELD` | 必填字段缺失 | 02 §2.4 |
| `DSL_DUPLICATE_NODE_ID` | 节点 ID 重复 | 02 §2.4 |
| `DSL_INVALID_ENTRY` | `entry_points` 指向不存在的节点 | 02 §2.4 |
| `DSL_INVALID_EDGE_REF` | 边引用不存在的节点 | 02 §2.4 |
| `DSL_INVALID_PORT` | `to_input_port` 未在目标节点声明 | 02 §2.4 |
| `DSL_DUPLICATE_EDGE` | 同 `(from, to_node)` 重复 | 02 §2.4 |
| `DSL_DUPLICATE_PORT_SOURCE` | 同一 `(to_node, to_input_port)` 有多条入边 | 02 §2.4 |
| `DSL_UNCONNECTED_INPUT` | 非 entry 节点 required input 无来源 | 02 §2.4 |

> **W2a0 运行期注记（defer 边 / attempt-per-activation）**：本批**不新增运行期错误码**，复用既有码并按 03 §3.4.3/§3.10 的语义使用——
> - `RUN_DELIVERY_TO_TERMINAL`：defer 边放行但目标为 `end` 且当前实例已 `Completed`（end 是 run 级聚合，重入未定义）、或目标终态非 `Completed`（防御性）；**defer 边目标为普通节点且已 `Completed` 时例外为 attempt-per-activation，不报此码**。
> - `RUN_DEADLOCK`：静默且存在 `DeferredReceipt` 的目标节点**从未实例化**（确定性判定，不等 `deadlock_grace`）；宽限期路径（静默 + Pending）保持不变。
> - `NODE_INTERNAL`：defer 重入时新实例 `attempt >= max_attempts` → 新实例 `Crashed(Internal)` → run `Failed`（与自环超限同风格，message 区分 `self-loop` / `defer re-entry`）。

## 0.6 不变式（Violation = 框架 bug，debug 构建 `assert!`，release 转 `RUN_ILLEGAL_TRANSITION` 或 `Internal`）

| # | 不变式 | 违反时 |
|---|---|---|
| I1 | **实例单次执行**：同一 `InstanceId` 的 `run()` 至多调用一次；自环/重试产生新 `Attempt` | Internal |
| I2 | **状态单调**：只允许 01 §1.3 迁移矩阵中的迁移 | RUN_ILLEGAL_TRANSITION |
| I3 | **buffer 先于执行**：进入 Running 前，`trigger=all` 的全部 required 端口已在 buffer；`trigger=any` 至少一个 required 端口已到（其余为 `null`） | Internal |
| I4 | **每边至多一次投递**：单次 publish 中，每条边至多产生一个 Delivery | Internal |
| I5 | **run 终态唯一**：`RunFinished` 恰好发一次，且 status 为终态 | Internal（事件去重） |
| I6 | **trace 因果完整**：`RunStarted` / `Transition` / `GateResult` / `NodeTimedOut` / `NodeAbandoned` / `RunFinished` 不可丢（见 §0.3 TraceEvent；`NodeAbandoned` v2 不产生，D1）；`Streaming` 可丢但有计数。**存储不可写 = fail-stop**：run 标 Failed，CLI 退出码 4（06 §6.4.5；M2 仅暴露写线程错误，生命周期接线 M3/M5） | 告警 + 指标；fail-stop |
| I7 | **门控纯函数**：gate 只读 `output + GateContext`，不写全局、不发事件、不改数据；异常/panic 视为不通过 | 拦截 + warning |
| I8 | **事件循环线程不执行 Python**：任何同步 Python 调用必须离开事件循环线程 | Internal |
| I9 | **冷峻失败**：任一实例 `Crashed` / `TimedOut` → run 立即 `Failed`，其余非终态实例转 `Cancelled` | — |

> **W3a0 解释（不改 I1/I9 语义）**：`WaitingHuman` 实例**从不执行 `run()`**，`WaitingHuman→Completed` 是该实例**唯一一次完成**（决策不重跑、不重入）；W2a 的 defer 重入产生**新实例/新 attempt**，不是对旧实例的重复执行。I9 仍成立：human 决策期限到期 = `TimedOut` → run `Failed`，其余 `WaitingHuman` 转 `Cancelled`。

## 0.7 术语与消歧（v1.1 歧义在此统一）

| v1.1 说法 | v1.2 统一为 |
|---|---|
| gate 的 `ctx: &RunContext`（6.5）vs `NodeContext`（5.2） | **GateContext**（只读：`user_id`/`get_var`/`params`），见 04 §4.6 |
| `EdgeRef { edge: &'static CompiledEdge }` | **`EdgeRef(EdgeIdx)`**，边数据从 `CompiledGraph.edges[..]` 取，见 01 §1.2 |
| `Delivery` 无目标实例字段 | **必填 `to_instance`**（旧称 `to_instance_id` 作废），见 01 §1.4 |
| `run.buffers.write(...)` | `RunState::buffer_write(instance_id, port, value)`，见 03 §3.4 |
| "实例只跑一次" vs HumanInput 重跑 | **W3a0**：`WaitingHuman` 不执行 `run()`，决策只触发一次 `WaitingHuman→Completed`（不重跑）；durable resume/崩溃后恢复留 W3b |
| "全 Completed" vs "全终态" | **无活跃实例（Pending/Ready/Running/WaitingHuman，W3a0 增等待态）** 即静默；冷峻失败优先，见 03 §3.9/§3.10 |
| 超时 30s（4.3）vs LLM 60s（3.4） | 实例 180s / LLM 60s / 工具 30s，见 §0.5 |
| `run()` panic | 捕获为 `NodeError::Internal` → Crashed → run Failed（不 unwind 事件循环） |
| optional 端口未到 | **全部声明端口都出现在 `inputs` 中，未到值为 `null`**（Python 侧 `None`）；`trigger=any` 的未到 required 端口同样为 `null` |
| gate=false 的处置（v1.1 消歧） | **缺省 settle**：结算入边 + `Skipped` 级联；**仅当边标 `on_gate_false:"defer"`** 时改为「挂账 `DeferredReceipt`、不结算、不 Skipped」（02 §2.2.2 / 03 §3.4.3） |
| 目标实例已 `Completed`（v1.1 消歧） | 普通边 → `RUN_DELIVERY_TO_TERMINAL`；**defer 边（非 `end`、非自环）→ attempt-per-activation 新实例**（**按端口继承**：仅入边 `on_gate_false != defer` 的 `values`/`arrived`，defer 端口必须新一代重投）；defer 边目标为 `end` → 仍 `RUN_DELIVERY_TO_TERMINAL`（03 §3.4.3） |

> **W4a 设计注记（2026-11-01，REV-086；不写 as-built）**：foreach region 的 item 实例是**同一节点**的多个实例（由 `item_index` 区分），I1「同一 `InstanceId` 的 `run()` 至多一次」仍成立；`controller buffer` 不是实例、不派发。实例定位键在 region 内为 `(node_id, item_index)`，非 region 恒 `item_index=0`（01 §1.2.5）。
