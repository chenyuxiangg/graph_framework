### 8.3.2 实质语义冲突（高，9 条；建议开工前回填）

**I-01｜03 §3.5「optional 未到端口不出现」 vs 01 §1.3 / 00 §0.7 / 04 §4.3.2「全部声明端口存在，未到为 null/None」**
- 03 原文：「`trigger=Any` 的未到 required 端口填 `null`；optional 未到端口**不出现**（04 §4.3）」
- 01 §1.3：「**全部声明端口都出现在 `inputs` 中**：optional 未到 = `null`」；00 §0.7 同；04 §4.3.2 表：「该节点 DSL 中声明的**每一个** input port 一定存在（无 KeyError）」。
- 影响：实现者若照 03 写 `build_inputs_snapshot`，Python 节点对 optional 端口取值会 `KeyError`；AC-01/AC-05 的节点代码可能随机失败。
- 建议改法：03 §3.5 该行改为「全部声明端口都写入 `inputs`；未到（含 optional 与 any 未到的 required）一律 `null`」，删除"不出现"。

**I-02｜03 §3.15「trace 写失败 → 标记降级，继续执行」 vs 06 §6.4.5「fail-stop，取消 run，退出码 4」**
- 03 §3.15 行：「trace 写失败（磁盘满）｜写线程｜**标记降级，继续执行**，退出时告警｜run 不受影响｜warning」。
- 06 §6.4.5：「磁盘满 / IO 错误 / DB 损坏｜**不可恢复**：通知调度器取消 run（内存态 Failed）…退出码 4」；06 §6.12.3 D2 仍标"需 lead 确认"。
- 影响：trace 可靠性与 run 结果的耦合关系未定；实现两条路都能自洽但行为相反。
- 建议改法：以 06 为准（I6 因果完整优先）——03 §3.15 改为 fail-stop（run Failed + exit 4），并在 00 I6 增一句"存储不可写 → run Failed"；同步关闭 06 D2。

**I-03｜04 §4.3.6「`exec_class` 缺省 `cpu`」 vs 00 §0.5 / 02 §2.2.1「默认 `io`」**
- 04 §4.3.6：「类别来源：`GraphNode.config.exec_class: "cpu" | "io"`，缺省 `"cpu"`…；若 02 未提供该字段，v1 所有 Python 节点按 `Cpu` 处理」。
- 00 §0.5：`PYTHON_EXEC_CLASS_DEFAULT = io`；02 §2.2.1：`exec_class` 缺省 `io`。
- 影响：默认 `cpu` 会让 Python I/O 节点串行（permits=1），**07 AC-09「a、b 同时进入 Running、总耗时 < 0.45s」将直接失败**；默认 `io` 则 I/O 节点可并行。
- 建议改法：04 §4.3.6 改为缺省 `io`，删除"若 02 未提供…按 Cpu"的兜底句（02 已提供）。

**I-04｜04 §4.1.4「`NodeError::Timeout` 仅调度器可产生」 vs 05 §5.3.6 / §5.7.2「Harness deadline 自检可产生 `NodeError::Timeout`」**
- 04 §4.1.4：Timeout「**仅调度器**（实例 deadline）」；归一化规则 1：handler 返回 `Err(Timeout)` → 按 `Internal` 处理。
- 05 §5.3.6：「Harness deadline 自检…返回 `NodeError::Timeout{elapsed_ms}`（与调度器同语义，不抢跑状态）」；§5.7.2 补充映射同。
- 影响：AgentCallHandler 把 Harness 的 Timeout 原样返回时，按 04 会被改写成 `Internal` → 实例 Crashed 而非 TimedOut，run 错误码变成 `RUN_ILLEGAL_TRANSITION/Internal` 而非 `NODE_TIMEOUT`；AC-06（agent 场景）不可预期。
- 建议改法：二选一并写死：(a) 04 §4.1.4 增例外「Harness 预检超时可返回 Timeout，调度器按 TimedOut 处理」；(b) 05 改为返回专用 `HarnessErrorKind::InstanceTimeout` 由执行器转 `NodeError::Timeout`。推荐 (a)（改动最小）。

**I-05｜05 §5.5.4 使用 `ctx.node_deadline_remaining_ms()` / `ctx.cancel_token()`，04 §4.2.2 未定义这两个方法**
- 04 §4.2.2 的 NodeContext 方法表只有：`emit` / `get_var` / `user_id` / `cancel_requested` / `check_cancelled` / `run_id` 等 getter / `new`。
- 05 §5.5.4 伪代码：`if ctx.node_deadline_remaining_ms() == 0`、`llm.chat_stream(..., ctx.cancel_token())`。
- 影响：Harness 无法按 05 实现；`CancelToken` 类型（05 §5.3.2）也无法从 ctx 取得。
- 建议改法：04 §4.2.2 增两个方法——`fn node_deadline_remaining_ms(&self) -> u64`、`fn cancel_token(&self) -> CancelToken`（或 05 改为用 `cancel_requested()` + 由执行器传入 deadline/CancelToken 参数，二者择一）。

**I-06｜07 AC-01 / 06 §6.10.6 的 `run_output` 与 04 §4.5.1 / 05 §5.9.2 的 agent 输出契约不一致**
- 04 §4.5.1：下游端口收到**整个 output 对象**；05 §5.9.2：`agent_call` 输出固定 `{content, stop_reason, iterations, usage}`。
- 02 示例：`answer_generator` 是 `agent_call`，其 output 应是四字段；`end_success.inputs.result` = 整个 output；按 01 §1.9 `run_output = {"result": {content, stop_reason, iterations, usage}}`。
- 07 AC-01 却断言「`run_output` 含 `end_success` 的输入（**含 `answer` 字段**）」；06 §6.10.6 示例直接给出 `"run_output": {"answer": "可以退款", "need_human": false}`。
- 影响：AC-01 按现断言会失败；实现者会怀疑"是不是要做字段级路由"（而 v1 明确整包广播）。
- 建议改法：断言改为「`run_output.result.content` 非空，解析其 JSON 后含 `answer`」；06 §6.10.6 的示例改成整包广播形状（`{"result": {"content": "{\"answer\":...}", ...}}`）。

**I-07｜07 AC-03「每个实例首个迁移为 Pending→Ready」 vs 01 §1.2.3 / 03 §3.4.2（Skipped 是 Pending→Skipped）**
- 01 §1.2.3 矩阵：Pending→Skipped = "入边全部结算且无数据"；03 §3.4.2 `maybe_skip` 直接把 Pending 实例标 Skipped（不经过 Ready）。
- 07 AC-03 断言「每个实例的迁移链合法…**首个迁移为 `Pending→Ready`**，末迁移为终态」。
- 影响：AC-01/AC-02（`human_handoff` 为 Skipped）无法同时满足 AC-03。
- 建议改法：改为「首迁移 ∈ {`Pending→Ready`, `Pending→Skipped`}；末迁移为终态」，并注明 Skipped 实例只有一条迁移。

**I-08｜07 AC-05「`RunFinished.error.code` 对应 `PythonException`」在 00 §0.4 中无此码**
- 00 §0.4 运行期域只有 `RUN_*` / `NODE_TIMEOUT` / `NODE_ABANDONED` / `NODE_TYPE_UNSUPPORTED`；Harness 域才有 `HARNESS_*`。Python 节点的 `PythonException` / `BusinessError` / `Internal` / `Config` 没有对应的 run 级码。
- 06 §6.2.5 `instances.error_code` 声明"值域 = 00 §0.4"，同样覆盖不到这些变体。
- 影响：AC-05 无法断言；CLI 失败输出 `error.code` 对 Python 节点异常该填什么没有权威答案（会各自发明）。

**I-09｜07 §7.1 验收资产与 02 §2.3.1 示例图不匹配（AC-01 目前跑不通）**
- 02 示例引用：gate `gates.hr.need_human`、python node `gates.hr.need_human_check`、4 个 agent 资产（`message_parser` / `kb_searcher` / `answer_writer` / `human_handoff_agent`）。
