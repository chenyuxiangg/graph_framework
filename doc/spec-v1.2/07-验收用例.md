## AC-01 示例图端到端跑通

- **前置**：`--fake-llm`，脚本让 `input_parser` 返回 `{"parsed_query":"退款政策","user_id":"u1"}`、`kb_search` 返回 `{"kb_result":{"hits":1}}`、`answer_writer` 返回 `{"answer":"可以退款","need_human":false}`。
- **步骤**：
  ```bash
  zgraph validate examples/customer_ticket/graph.json
  zgraph run examples/customer_ticket/graph.json \
    --inputs '{"input_parser":{"user_message":"我要退款"}}' --fake-llm --db /tmp/ac01.sqlite --json
  ```
- **预期**：
  - `validate` 退出码 0，人类可读输出匹配 02 §2.7.4 格式（`✓ graph valid: 6 nodes, 6 edges, 0 subgraphs (graph_hash=…)`）；
  - `run` 退出码 0，JSON 中 `status="Completed"`；`run_output = {"result": <answer_writer 整包 output>}`，`run_output.result.content` 为字符串（需二次解析出 `answer`、`need_human`），`run_output.result.stop_reason` 存在（整包广播语义，04 §4.5 / 05 §5.9.2）；
  - 实例状态序列：`input_parser`、`kb_search`、`answer_generator`、`human_escalation_check` 均 `Completed`；`human_handoff` 为 `Skipped`（gate 拦截）；`end_success` `Completed`。
- **验证 SQL**：`SELECT node_id,status FROM instances WHERE run_id=?;`

## AC-02 门控拦截与 Skipped 级联

- **步骤**：同 AC-01（`need_human=false` 触发拦截）。
- **预期**：
  - `gate_results` 表恰有一条 `passed=0`（edge: `human_escalation_check → human_handoff`）；
  - `human_handoff` 状态 `Skipped`（不是 Pending）；其下游（若有）级联 `Skipped`；
  - `end_success` 仍 `Completed`（拦截不影响另一分支）；
  - 反向用例：`need_human=true` 时 `human_handoff` `Completed`。
- **验证**：`SELECT passed FROM gate_results WHERE run_id=?;` + `zgraph trace <run_id>` 中出现 `gate blocked` 行。

## AC-03 trace 完整性与回放

- **步骤**：跑 AC-01 后执行 `zgraph trace <run_id> --json > trace.json`。
- **预期**：
  - 事件序列以 `RunStarted` 开头、`RunFinished` 结尾，**恰好各一次**（I5）；
  - 每个实例的迁移链合法（用 01 §1.2.3 矩阵校验）：首迁移 ∈ {`Pending→Ready`, `Pending→Skipped`}（Skipped 实例只有这一条迁移），末迁移为终态；
  - `seq` 单调递增；`zgraph trace` 能按 seq 重建时间线；
  - 不可丢事件数 = 预期数（无缺口）；
  - Streaming 事件可按 instance 聚合为文本，且 `RunFinished.metrics.streaming_dropped` 可读。
- **验证 SQL**：`SELECT count(*) FROM events WHERE run_id=? AND kind='RunFinished';`（=1）
  `SELECT from_status,to_status FROM transitions WHERE instance_id=? ORDER BY seq;`（矩阵校验）

## AC-05 冷峻失败：Python 异常

- **前置**：`nodes/boom.py` 抛 `RuntimeError("boom")`；图：`start → boom → end`。
- **预期**：
  - `boom` 实例 `Crashed`，`instances.error_json` 含 `PythonException.message` 与 `traceback`（多行）；
  - run `Failed`，`RunFinished.error.code = NODE_PYTHON_EXCEPTION`（00 §0.4），**不等待**其它分支；
  - 其它在跑实例被标 `Cancelled`（冷峻 I9）；
  - 解释器仍健康：同一进程随后再跑 AC-01 成功（`cargo test` 中顺序断言）。

## AC-06 超时 stop-waiting 不挂死

- **前置**：`nodes/slow.py` 执行 `time.sleep(30)`；节点 `timeout_ms=1000`。
- **步骤**：`zgraph run ... --json`，计时。
- **预期**：
  - 进程在 **≤ 5s** 内返回（不等待 30s），退出码非 0；
  - 实例 `TimedOut`，run `Failed`（`NODE_TIMEOUT`）；
  - trace 有 `NodeTimedOut`；进程组被 kill、无残留子进程（v2 偏差 D1：`NodeAbandoned` 不产生，`abandoned_tasks` 恒 0）；
  - 进程正常退出（`shutdown_timeout` 生效）。

## AC-07 事件循环不阻塞

- **方法**：测试内注入 5ms ticker（复用 `doc/analysis/spike/src/bin/t2_gil.rs` 方法；spike 源已入库），跑含 Python 节点/gate 的图（每节点 sleep 0.3s）。
- **预期**：事件循环 ticker 最大间隔 **< 50ms**；Python 节点执行期间循环仍能处理控制命令（Pause 在 100ms 内生效）。
- **反例保护**：若把 Python 调用放回事件循环线程，本用例必须失败（用编译期/运行期断言守住）。

## AC-08 真实 LLM + tool loop + 流式（手动）

- **前置**：`DEEPSEEK_API_KEY`；`--real`；`answer_writer` 允许调用 `now` 工具。
- **步骤**：跑 AC-01 的图（agent 节点真实模型）。
- **预期**：
  - `agent_call` 节点 `Completed`，输出含 `{content, stop_reason, iterations, usage}`；
  - trace 中出现 `ToolCallStart/ToolCallEnd`（至少一次）与 `TokenDelta`（聚合后非空）；
  - `iterations ≥ 1`，`usage.total_tokens > 0`；
  - 重跑 3 次成功率 ≥ 2/3（容忍模型波动），失败时错误码映射正确。

## AC-09 并行分支与确定性

- **图**：`start → {a_py, b_py} → merge → end`（a/b 为 Python sleep 0.2s，merge 需两输入）。
- **预期**：
  - a、b 的 Running 区间重叠（时间差 < 50ms），总耗时显著小于串行（含进程冷启动；M3 实测后定阈值，初值 < 1.0s；v2 偏差 D8）；
  - `merge` 收到两端口各一份数据；`trigger=all` 就绪语义正确；
  - **确定性**：同输入连续 5 次 run，`transitions` 的节点顺序集合一致（允许并行分支内部交错，但状态与最终输出一致）；
  - 覆盖语义：同一端口两次投递时后者覆盖（v1 单数据源），trace 可见两条投递。

## AC-10 暂停/恢复/取消

- **暂停**：run 含 2 个串行 Python 节点（各 0.3s），第 1 个执行中发 Pause → 第 2 个不派发；等待 1s 无新 Running；Resume 后完成。
- **取消**：执行中发 Cancel → run `Cancelled`、无 `Failed`；在飞实例 `Cancelled`；`RunFinished` 恰一次；后续事件被忽略。
- **幂等**：重复 Pause/Resume/Cancel 不改变结果、不重复 `RunFinished`。

## AC-11 死锁检测

- **图构造**：`a → b`，但 a 的出边 gate 恒 false，且 b 是唯一 end 的前置。
- **预期**：
  - b 被级联 `Skipped`（若其全部入边结算）→ run 正常 `Completed`，**不**误报死锁；
  - 人为制造"入边永不结算"：测试构建启用 `RunOptions.test_hooks.disable_settle=true`（03 §3.2，`feature = "test-hooks"`）→ 静默超过 `deadlock_grace_ms` 后 run `Failed`，`error.code=RUN_DEADLOCK`，不无限挂起。生产构建无该入口。

## AC-12 多 run 并发隔离

- **步骤**：并发启动 10 个 AC-01 run（同图、不同 `run_id`、独立 db 或同 db 不同 run_id）。
- **预期**：
  - 全部 `Completed`；每个 run 的 `instances/gate_results/events` 只属于自己；
  - `global_vars`/`user_id` 不串；
  - 全局 `max_workers` 与每 run `max_workers_per_run` 上限生效、run 间隔离（v2 偏差 D8/D4；不再使用 CPU=1/IO=4 信号量）；
  - 观测总耗时与单 run 之比合理（I/O 型近线性，CPU 型受 GIL 限制，记录基线）。
