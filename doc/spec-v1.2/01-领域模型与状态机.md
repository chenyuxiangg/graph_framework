## 1.1 编译期产物

### 1.1.1 `CompiledGraph`

```rust
pub struct CompiledGraph {
    pub graph_hash: GraphHash,
    pub metadata: GraphMetadata,
    pub nodes: HashMap<NodeId, CompiledNode>,     // 节点表
    pub node_order: Vec<NodeId>,                  // DSL 声明顺序（end 聚合、遍历确定性）
    pub edges: Vec<CompiledEdge>,                 // 边表，索引 = EdgeIdx（数值别名，00 §0.2）
    pub entry_points: Vec<NodeId>,
    pub subgraphs: HashMap<SubgraphId, Arc<CompiledGraph>>, // v1 仅校验，不执行
}

pub struct CompiledNode {
    pub id: NodeId,
    pub node_type: NodeType,
    pub inputs: Vec<InputPort>,       // 声明顺序即校验/展示顺序
    pub outputs: Vec<OutputPort>,     // v1 保留（通常为空）
    pub trigger: Trigger,             // All | Any
    pub handler: HandlerRef,          // Start | End | Python { module, function } | Agent { agent_id, input_mapping } | Subgraph { id }
    pub timeout_ms: u64,              // 节点 config 覆盖或 DEFAULT_NODE_TIMEOUT_MS；实例超时唯一来源
    pub max_attempts: u32,            // 默认 DEFAULT_MAX_ATTEMPTS；自环与 defer 重入统一上限（W2a0）
}

pub struct CompiledEdge {
    pub index: EdgeIdx,               // == 数组下标，编译期断言（ISSUE-043）
    pub from: NodeId,
    pub to_node: NodeId,
    pub to_port: PortName,
    pub gate: Option<GateRef>,        // 全限定符号 module.function + params

```

**强制约束**：`CompiledGraph` 构造后不可变（`Arc<CompiledGraph>` 只读共享）；所有表在编译期完成，运行期不再增删节点/边。`CompiledEdge.on_gate_false` 恒有值（DSL 缺省 `settle` 在编译期补齐；**不写回 DSL、不参与 `graph_hash`**，02 §2.8.3）。

### 1.1.2 边索引（修正 v1.1 的 `EdgeRef` 自引用问题）

```rust
pub struct EdgeIndex {
    pub outgoing: HashMap<NodeId, Vec<EdgeIdx>>,          // 发布扇出
    pub incoming: HashMap<(NodeId, PortName), EdgeIdx>,   // 入边唯一（见下）
    pub incoming_by_node: HashMap<NodeId, Vec<EdgeIdx>>,  // 节点全部入边（就绪/Skipped 判定）
}

pub struct EdgeRef(pub EdgeIdx);   // 轻量句柄；取边数据：graph.edges[EdgeRef.0]
```

**裁定**：v1.1 的 `EdgeRef { edge: &'static CompiledEdge }` 是自引用结构，Rust 中不可构造，**删除**，统一为 `EdgeIdx` 数组下标。
**命名（ISSUE-043，M2 回写）**：`EdgeIndex` = 本节的**索引结构体**；`EdgeIdx = usize` = 边的**数值标识**（00 §0.2）。v1.2 冻结时二者同名冲突，M2 保留结构体名、数值别名改 `EdgeIdx`，字段/签名语义不变。
**唯一性**：`(to_node, to_port)` 至多一条入边（`DSL_DUPLICATE_PORT_SOURCE`）；`(from, to_node)` 至多一条边（`DSL_DUPLICATE_EDGE`）。这使「单数据源、后到覆盖先到」语义成立（见 1.8）。

### 1.2.2 `InstanceKey` 与寻址（关闭审计 M-13/S-02）

| 问题 | 裁定 |
|---|---|
| 一个节点能有几个实例？ | v1 **同时至多一个活跃实例**；`RunState.node_current: HashMap<NodeId, InstanceId>` 记录当前实例 |
| 下游实例何时创建？ | **惰性**：第一条投递到达时创建（`Pending`，`attempt=0`）；entry 节点在 run 启动时创建 |
| 自环（from == to_node）怎么处理？ | 每次投递**创建新实例**（`attempt = 发布者实例.attempt + 1`），旧实例保持 `Completed`；`attempt > max_attempts-1` → 目标实例直接 `Crashed{Internal}`，run Failed（防死循环） |
| 投递到已终态实例？ | 普通边（settle）→ `RUN_DELIVERY_TO_TERMINAL`，run Failed（fail-fast；正常 DAG 不应发生） |
| **defer 边投递到已 `Completed` 实例？** | **W2a0**：普通节点 → **attempt-per-activation**：新建实例 `attempt = 目标当前实例.attempt + 1`，并**按端口继承 + 清空节点级 settled 集**（§1.4.1，Lead 裁决补全）；`attempt > max_attempts-1` → 新实例 `Crashed{Internal}` → run `Failed(NODE_INTERNAL)`。`end` 节点 → 仍 `RUN_DELIVERY_TO_TERMINAL`（run 级聚合，重入未定义） |
| **defer 边 gate=false 怎么处理？** | **W2a0**：不创建/不寻址目标实例；只记 `GateResult{deferred=true}` + 更新 `DeferredReceipt`（§1.4.1）；**不结算入边、不触发 Skipped** |
| `Delivery.to_instance` 怎么填？ | 发布时解析：自环 → 新实例 id；defer 边目标已 `Completed` → 新尝试实例 id；否则 → `node_current` 中的实例，不存在则创建 |

### 1.2.3 状态机迁移矩阵（关闭审计 M-12；I2 的可执行版本）

| From \ To | Ready | Running | Completed | Crashed | TimedOut | Cancelled | Skipped |
|---|---|---|---|---|---|---|---|
| **Pending** | 输入就绪 | — | — | — | — | run 取消/失败 | 入边全部结算且无数据 |
| **Ready** | — | 调度派发 | — | — | — | run 取消/失败 | — |
| **Running** | — | — | 执行成功 | 执行失败 | 超时 | run 取消/失败/协作取消 | — |
| **终态** | — | — | — | — | — | — | — |

**迁移副作用（必须原子完成）**：

| 迁移 | 副作用 |
|---|---|
| Pending→Ready | 写 `TransitionRecord`；加入就绪队列 |
| Ready→Running | 写 `TransitionRecord`；记 `started_at`；启动超时计时；派发执行任务 |
| Running→Completed | 写 `TransitionRecord`；记 `finished_at`/`output`；触发 publish |
| Running→Crashed | 写 `TransitionRecord`；记 `error`；**冷峻**：run → Failed（见 03 §3.7） |
| Running→TimedOut | 写 `TransitionRecord` + `NodeTimedOut` 事件；**冷峻**：run → Failed |
| Running→Cancelled | 写 `TransitionRecord`；协作取消标志；不等待任务返回 |
| *→Skipped | 写 `TransitionRecord`（reason=`all_sources_blocked`）；把该节点全部出边标记"结算-无数据"并级联 |
| 任意→终态 | 从活跃集合移除；触发终止判定（03 §3.9） |

**非法迁移**：返回 `NodeError::Internal{RUN_ILLEGAL_TRANSITION}`，run Failed（框架 bug，不静默修复）。

## 1.3 输入缓存

```rust
pub struct InstanceBuffer {
    pub values: HashMap<PortName, Value>,   // 单数据源语义：后到覆盖先到（v1 不做 reducer）
    pub arrived: HashSet<PortName>,
    pub required: HashSet<PortName>,        // 编译期从 CompiledNode.inputs 预置
    pub settled_sources: HashSet<EdgeIdx>,// 已结算入边（投递成功或 gate 拦截；W2a0 裁决：实现仅审计/排障，不参与 skip/就绪判定）
    pub gate_results: Vec<GateResultRecord>,
}
```

**就绪判定（I3）**：

```text
ready(inst) =
  trigger == All  →  required ⊆ arrived
  trigger == Any  →  arrived ∩ required ≠ ∅
```

- `trigger=Any` 触发时，未到的 required 端口在传给节点前**显式填 `null`**（Python 侧为 `None`）。
- **全部声明端口都出现在 `inputs` 中**：optional 未到 = `null`；`trigger=any` 的未到 required 端口 = `null`（Python 侧统一为 `None`，可用 `inputs["x"]` 直接取）。
- 就绪判定只在**投递处理**后执行一次（不在读 buffer 时反复判定），避免重复派发。
- **W2a0（defer 重入实例的 buffer 初始化）**：按 §1.4.1 的 **per-port** 规则——只把「该端口入边 `on_gate_false != Defer`」的 `values`/`arrived` 从上一代实例深拷贝；入边为 defer 的端口必须由新一代投递填充（否则旧评审结论会让 `P` 提前就绪）。结算状态**统一按节点级 `settled_by_node`** 处理；实例级 `settled_sources` 仅审计/排障、不参与判定（N-9）。

## 1.4 投递契约（关闭审计 P-04/C-23/C-24）

```rust
pub struct Delivery {
    pub run_id: RunId,
    pub from_instance: InstanceId,
    pub from_node: NodeId,
    pub edge_index: EdgeIdx,
    pub to_node: NodeId,
    pub to_instance: InstanceId,
    pub to_port: PortName,
    pub data: Value,                     // v1 = 发布者 output 整包
    pub gate: Option<GateOutcome>,       // None = 无门控（恒放行）
    pub delivered_at: DateTime<Utc>,
}

pub struct GateOutcome { pub gate_fn: String, pub params: Value, pub passed: bool, pub error: Option<String> }

pub struct BlockedDelivery {
    pub run_id: RunId, pub from_instance: InstanceId, pub edge_index: EdgeIdx,
    pub to_node: NodeId, pub to_instance: Option<InstanceId>, pub to_port: PortName,
    pub gate_fn: String, pub reason: String, pub blocked_at: DateTime<Utc>,
}

pub struct PublishResult { pub deliveries: Vec<Delivery>, pub blocked: Vec<BlockedDelivery> }
```

**语义（比 v1.1 更严，修正双写问题）**：

0. **两阶段**：gate 求值在**执行任务内 off-loop** 完成（结果随 `NodeCompleted.evaluations` 回传）；事件循环只做**寻址 + 应用**（生成 Delivery/BlockedDelivery 并写 buffer，03 §3.4）。`publish()` 是事件循环内的纯寻址/应用函数，**不调用 Python**。
1. `publish()` **只做寻址与组装**：遍历 `outgoing[from_node]`，取用已求值的 gate 结果，生成 `Delivery`/`BlockedDelivery`；**不写 buffer**。
2. 事件循环拿到 `PublishResult` 后**统一应用**：`Delivery` → 写 buffer + 结算入边 + 就绪判定；`BlockedDelivery` → 结算入边（无数据）+ 级联 Skipped 判定。
3. 因此"publish 返回时投递已落 buffer"成立**在事件循环视角**（同一线程顺序应用），不存在 v1.1 的两次写。
4. 每次 publish 中，每条边至多一个 Delivery（I4）；同一 `to_instance` 的不同端口投递顺序 = `edges` 数组顺序（确定性）。

### 1.4.1 defer 边与 `DeferredReceipt`（W2a0）

**结论**：defer 边的 gate=false **不产生 `Delivery`、不产生 `BlockedDelivery`、不结算入边**，改用运行期挂账 `DeferredReceipt` 表达「这条边已经判过 false、但还没有被放弃」；dormant/死锁判定只依赖 receipt 的**目标节点当前实例状态**（03 §3.10）。

```rust
/// 一条 defer 边最近一次 deferred 决策的挂账记录（W2a0）。
/// key = EdgeIdx；不因后续放行删除（"最近一次 deferred 决策"语义，DR-005 §11 E-3）。
pub struct DeferredReceipt {
    pub edge_index: EdgeIdx,
    pub source_instance: InstanceId,  // 做出 deferred 决策的发布者实例
    pub source_attempt: Attempt,      // 该实例 attempt（审计/排障）
    pub target_node: NodeId,          // = CompiledEdge.to_node
    pub updated_at: String,          // 实现口径：RFC3339 毫秒 Z（与既有 ts/at 同口径；W2a 裁决）
}
```

| 规则 | 规定 |
|---|---|
| 写入时机 | 仅 `CompiledEdge.on_gate_false == Defer` **且** `gate=false`；同一 `EdgeIdx` 重复 deferred → 覆盖并刷新 `updated_at` |
| 不写入 | settle 边 gate=false（走 v0.1.0 的 `BlockedDelivery` + 结算 + `maybe_skip`）；gate=true 的 defer 边（走投递/attempt-per-activation） |
| 与 `BlockedDelivery` 的关系 | 互斥：defer 挂账用 receipt；settle 拦截用 `BlockedDelivery`。**不允许**同一次 gate=false 既写 receipt 又结算入边 |
| attempt-per-activation 的 buffer 继承（**per-port**） | defer 边放行且目标当前实例 `Completed` → 新实例**只继承「入边 `on_gate_false != Defer`」的端口**：`values[p]`/`arrived[p]` 深拷贝；**入边为 defer 的端口不继承**（值/arrived 都不继承，必须新一代重投）。结算按节点级 `settled_by_node` 处理（实例级 `settled_sources` 不参与判定）。`required` 由编译期节点重建、`gate_results` 不继承（DR-005 §3.2 行 6/7） |
| 重入时的节点级结算集 | **创建 defer 重入实例时清空 `RunState.settled_by_node[target_node]`**（W2a0，Lead 2026-10-31 裁决）：避免上一代「全部入边已结算」使新 Pending 实例被 `maybe_skip_after_settle` 误判 `Skipped`。实现**统一按节点级 `settled_by_node`**；实例级 `settled_sources` 若保留仅审计/排障、不参与 skip/就绪判定（N-9）。v0.1.0 无重入实例 → 行为不变 |
| 生命周期 | 不因放行删除；不参与 `graph_hash`；不进 `Delivery`；trace 通过 `GateResultRecord.deferred=true` 可观测 |

## 1.7 事件类型（最终版）

```rust
pub enum RuntimeEvent {
    /// 派发任务回传：节点成功（含 off-loop 预先求值的出边 gate 结果）
    NodeCompleted {
        run_id: RunId,
        instance_id: InstanceId,
        output: Value,
        evaluations: Vec<GateEvaluation>,   // 每出边一条；见 1.4.1
    },
    /// 派发任务回传：节点失败
    NodeFailed { run_id: RunId, instance_id: InstanceId, error: NodeError },
    /// 派发任务回传：节点超时（由事件循环侧 deadline 判定，不经执行任务）
    NodeTimedOut { run_id: RunId, instance_id: InstanceId, elapsed_ms: u64 },
    /// 协作取消确认（节点自检后回传）
    NodeCancelled { run_id: RunId, instance_id: InstanceId },
}

pub struct GateEvaluation {
    pub edge_index: EdgeIdx,
    pub passed: bool,
    pub error: Option<String>,   // gate 异常/非 bool
    pub verdict: Option<Value>,  // W2a0：内置 check_output/compare 且 params.path 为 string 时的路径值
}
```

> **`verdict` 由执行任务 off-loop 求值时就地取出**（01 §1.5 / DR-005 §4.1），事件循环不二次求值、不读 `output` 取路径。

**为什么 gate 结果随 NodeCompleted 一起回传**：v2 的 gate 是**内置 op**（`check_output`/`compare`/`manual`，D6；不执行用户 Python），但求值仍放在**执行任务内 off-loop**（不在事件循环线程，I8）；执行任务在返回前求值全部出边 gate，事件循环只做确定性的投递应用（03 §3.4）。

**与 v1.1 的差异及理由**：

| v1.1 | v1.2 | 理由 |
|---|---|---|
| `InputArrived` 事件 | **删除** | 投递在事件循环内同步应用（1.4），再排队一次纯属多余跳转，且破坏"publish→buffer"原子性 |
| `HumanInput` 事件 | **删除**（v1.1 恢复） | v1 不做人工介入（D4） |
| `RunControl` 在 RuntimeEvent 内 | **独立高优先 mpsc** | v1.1 声称控制通道"优先消费"，但单 `recv` 无优先级（审计 C-13）；见 03 §3.8 |
| 无超时事件 | `NodeTimedOut` | 审计 M-18 |

## 1.8 不变量在结构上的落点

| 不变式（00 §0.6） | 落点 |
|---|---|
| I1 单次执行 | `instance.status` 迁移矩阵不允许 Running→Running；自环新建实例 |
| I2 状态单调 | 1.2.3 矩阵 + `transition()` 唯一入口 |
| I3 buffer 先于执行 | `ready()` 只在投递/启动注入后调用，派发前 `debug_assert!` 再检查一次 |
| I4 每边一次 | `publish()` 遍历 `outgoing[node]`，每个 `EdgeIdx` 至多生成一个 Delivery |
| I5 run 终态唯一 | `RunState.status` 终态后忽略后续事件；`RunFinished` 只由 `finish_run()` 发 |
| I6 trace 因果 | 不可丢事件走 `send().await`（03 §3.12），Streaming 走 `try_send` |
| I7 gate 纯函数 | `GateContext` 只读（04 §4.6）；gate 不参与 Delivery.data 改写 |
| I8 事件循环不跑 Python | `NodeContext` 只能由派发任务构造（04 §4.2）；事件循环内不 import/call Python |
| I9 冷峻 | `Crashed/TimedOut` → `fail_run()` 单入口（03 §3.7） |

> **W2a0 复核**：defer 边不改变 I1–I9——gate=false 的 defer 决策**不产生投递**（I4 仍「每边至多一次投递」）；attempt-per-activation 仍是**新实例**（I1 单次执行）；状态迁移仍走 1.2.3 矩阵（I2）；dormant/死锁判定只发生在静默之后（03 §3.10）。

## 1.9 run 输出（关闭审计 S-17）

| 规则 | 裁定 |
|---|---|
| `end` 节点输出 | 不 publish；其 **inputs 值集合** 作为该 end 的产出 |
| 单 end | `run_output = end.inputs`（`{}` 若空） |
| 多 end | 按 `CompiledGraph.node_order` 合并，**后者覆盖同名 key**；冲突记 warning |
| 无 end 执行（全部 Skipped） | `run_output = null`；run 仍可 `Completed`（合法：设计者主动门控掉整条链） |
| 失败 run | `run_output = null`，错误在 `RunFinished.error` |
| 输出位置 | 内存 `RunState.run_output` + SQLite `runs.output_json` |
