## 4.0 裁定摘要与编号约定

**结论：本分册共做 9 项契约级裁定，节点只通过受限 `NodeContext` 与框架交互，所有"用户代码"执行点一律离开事件循环线程。**

| # | 主题 | 一句话结论 | 详见 |
|---|---|---|---|
| 1 | `NodeHandler` | 单一 `run` 入口、`&self`、`Send + Sync`；v1 无 `resume`，v1.1 用**子 trait** 扩展而非改签名 | §4.1 |
| 2 | `NodeContext` | 不可变快照 + 有界可丢通道 + 原子标志；构造器 `pub(crate)`；**物理上不持有 RunContext** | §4.2 |
| 3 | `emit` | 同步 `fn`（Python 无 `await`），内部 `try_send` 非阻塞，满则丢弃并计数（streaming 属 I6 可丢类） | §4.2 |
| 4 | Python 节点 | 返回必须 `dict`，违反 → `BusinessError{code:"NODE_RETURN_NOT_DICT"}`；所有异常结构化，解释器不污染 | §4.3 |
| 5 | 签名校验 | 加载期强制 **arity/函数种类**（2 个必填参数、同步模块级函数、无变参）；**类型注解只告警不阻断** | §4.3.5 |
| 6 | 门控 | `gate(output, ctx) -> bool`，**严格 bool**：非 bool 一律拦截 + warning + trace，不使 run Failed | §4.6 |
| 7 | 门控数据 | gate **不能**修改/转换 payload（推翻 v1.1「gate 转换后的值」）；publish 永远使用原始 output | §4.6.3 |
| 8 | 子图 | 加载期校验通过，运行期在**派发前**拒绝：run Failed + `NODE_TYPE_UNSUPPORTED`，不创建实例、无 handler | §4.4.4 |
| 9 | 输出路由 | v1 整包广播：节点输出整体投递到每条出边的 `to_input_port`；节点自行取字段；`from_output_port` 仅 v2 | §4.5 |

**编号约定**：00 §0.7 以「见 04 §4.6」引用 GateContext，故本分册**固定 4.6 为门控契约**；为此输出路由排在 4.5、SymbolResolver 排在 4.7（与 00 的交叉引用严格一致）。

**错误码使用原则**：`DSL_*` / `RUN_*` / `NODE_*` / `HARNESS_*` / `TOOL_ERROR` 是 00 §0.4 的**顶层对外错误码**，本分册不新增。`NodeError::BusinessError.code` 是**载荷内业务码**，本分册只保留 `NODE_` 前缀的框架保留码（§4.3.2），用户业务码不得以 `NODE_` 开头。

## 4.1 `NodeHandler` trait

**结论：所有节点类型实现同一个 `NodeHandler`，只有一个 `run` 入口；handler 无状态、可跨实例并发共享；v1 不存在 `resume`，恢复语义通过 v1.1 新增子 trait 落地，不改动本签名。**

### 4.1.1 最终定义

```rust
/// 节点回调 trait —— 所有节点类型（含内置 start/end）实现这个接口。
/// 契约级伪代码：字段/方法名与语义强制；所有权写法可随 03 分册调整，但不得改变语义。
#[async_trait]
pub trait NodeHandler: Send + Sync {
    /// 执行节点逻辑。每个 InstanceId 至多调用一次（00 §0.6 I1）。
    ///
    /// # 参数
    /// * `inputs` —— 该节点**全部已声明 input port** 的映射；未到的端口值为 `Value::Null`
    ///               （含 trigger=any 下未到的 required 端口，见 00 §0.7 / 02 分册裁定）。
    /// * `ctx`    —— 受限运行时上下文，见 §4.2。
    ///
    /// # 返回
    /// * `Ok(output)` —— 节点成功；output 由调度器经门控后发布到出边（见 §4.5）。
    /// * `Err(e)`     —— 节点失败；映射规则见 §4.1.4。除 `Cancelled` 外一律 → Crashed。
    async fn run(
        &self,
        inputs: HashMap<PortName, Value>,
        ctx: &NodeContext,
    ) -> Result<Value, NodeError>;

    /// 仅 Python 类 handler 覆写；调度器据此选择 Python 并发信号量（§4.3.6）。
    /// 非 Python handler 保持默认 `None`，不占 Python 信号量。
    fn python_exec_class(&self) -> Option<PythonExecClass> {
        None
    }
}

/// Python 节点的执行类别（GIL 行为不同，见 _spike/REPORT.md §3.2）。
pub enum PythonExecClass {
    Cpu, // CPU 型：GIL 串行，并发上限默认 1
    Io,  // I/O 型（释放 GIL）：可并行，并发上限默认 4
}
```

**约束**：

| 约束 | 说明 | 依据 |
|---|---|---|
| `Send + Sync` | handler 对象可被多个执行任务共享；`&self` 保证无 `&mut` 别名 | 03 执行模型；spike §3.8 |
| `async fn` + `#[async_trait]` | future 必须 `Send`；**不得跨 `await` 持有 `Python<'_>` / `Bound` / `PyRef`**（PyO3 非 `Send`，编译器会拦） | spike §4.4 |
| 无状态 | handler 不得保存"本次执行"的可变状态；每次调用的全部上下文来自 `inputs + ctx` | 原 5.3「节点是纯函数」 |
| 单次调用 | 同一 `InstanceId` 的 `run` 至多一次；自环/重试 = 新 `InstanceId` + `attempt+1` | 00 §0.6 I1、01 分册 |
| panic 不外泄 | `run` 内 panic 由调度器 `catch_unwind` 捕获 → `NodeError::Internal{message}` → Crashed（不 unwind 事件循环） | 00 §0.7 |
| 超时不归 handler | handler **不得**返回 `NodeError::Timeout`；超时只由调度器计时器产生 | §4.1.4 |

### 4.1.2 handler 的归属与生命周期

| 节点类型 | handler | 构造时机 | 执行位置 |
|---|---|---|---|
| `start` | `StartHandler`（Rust 内置） | 图加载后由 Runtime 构造一次 | 事件循环任务内（纯内存操作，非阻塞） |
| `end` | `EndHandler`（Rust 内置） | 同上 | 同上 |
| `python_node` | `PythonNodeHandler`（Rust 内置，持有 `Arc<RegisteredFn>`） | 同上（符号已由 §4.7 解析） | `spawn_blocking` + Python 信号量 |
| `agent_call` | `AgentCallHandler`（05 分册） | 同上 | async（LLM I/O）；其工具执行见 05 |
| `subgraph` | **无 handler** | — | v1 派发前拒绝（§4.4.4） |

- handler 对象由图加载产出，按节点持有；同一 handler 被同一节点的不同实例串行调用（v1 单节点至多一个活跃实例，01 §1.4），但仍要求 `Sync` 以防未来并行化退化。
- 「注册」只发生在 Rust 代码编译期（内置 handler）与图加载期（Python 符号解析，§4.7）；用户不能运行期注入 Rust 代码（v1.1+ 才考虑 cdylib/wasm，见 §4.8）。

### 4.1.3 为什么 v1 没有 `resume` 入口

**结论：v1 不做人工介入，实例唯一一次执行（I1）使 `resume` 没有调用者；不得为它预留字段污染 v1 契约。**

| 事实 | 推论 |
|---|---|
| v1 不产生 `WaitingHuman`（00 §0.3、决策记录-01 D4） | 不存在"挂起后继续"的实例 |
| 实例严格执行一次（I1），Crashed/TimedOut 即终态 | `run` 的返回值只有"成功/失败"两态 |
| 失败语义冷峻：失败不重跑、不等待人工 | 无恢复入口需求 |

**v1.1 扩展位（不改本分册签名）**：新增**子 trait** 与**独立返回类型**，v1 的 `NodeHandler` 实现保持编译兼容：

```rust
// v1.1 预留（v1 不实现、不导出）
pub enum NodeOutcome {
    Done(Value),
    WaitHuman { request_id: String, prompt: String, schema: Value },
}
#[async_trait]
pub trait ResumableNodeHandler: NodeHandler {
    async fn resume(&self, request_id: &str, payload: Value, ctx: &NodeContext)
        -> Result<NodeOutcome, NodeError>;
}
```

> 之所以用子 trait 而不是在 v1 `run` 里加 `Option`/`todo!()` 字段：任何 v1.1 的返回类型扩展（`Result<Value,_>` → `Result<NodeOutcome,_>`）都会让所有 v1 用户 handler 编译失败，而对 v1 无收益。

### 4.1.4 `NodeError` → 实例状态映射（权威表）

**结论：`Err(e)` 的唯一默认后果是 Crashed；`Timeout` 只允许由调度器（实例 deadline）或 `AgentCallHandler`（Harness 预检超时，05 §5.3.6）产生，取消语义由 run 级标志决定。**

| `NodeError` 变体 | 允许的产生者 | 实例终态 | run 影响 | trace |
|---|---|---|---|---|
| `BusinessError { code, message }` | 任意 handler（Python 自定义异常映射，§4.3.4） | `Crashed` | run `Failed`（I9 冷峻） | error |
| `PythonException { message, traceback }` | 仅 `PythonNodeHandler` | `Crashed` | run `Failed` | error + traceback |
| `Timeout { elapsed_ms }` | ① **调度器**（实例 deadline）；② `AgentCallHandler`（Harness 预检：`ctx.node_deadline_remaining_ms()==0`，05 §5.3.6） | `TimedOut` | run `Failed`；另有 `NODE_ABANDONED` 记账告警 | warning/error |
| `Cancelled` | ① 调度器取消传播；② handler 协作取消（`ctx.check_cancelled()`，且仅当 `cancel_requested()==true`） | `Cancelled` | 用户取消 → run `Cancelled`；冷峻失败级联 → 属于 run `Failed` 的收尾 | info |
| `Harness { kind, detail }` | 仅 `AgentCallHandler`（05 分册 §5.7 映射） | `Crashed` | run `Failed` | error |
| `Config { message }` | handler 构造/运行期资产加载失败（如执行期才发现符号不可用） | `Crashed` | run `Failed` | error |
| `Internal { message }` | 框架不变量违反 / `run` panic（00 §0.7） | `Crashed` | run `Failed`（fail-fast） | error |

**归一化规则（实现必须遵守）**：

1. handler 返回 `Err(Timeout{..})`：**仅 `AgentCallHandler` 合法**（Harness 预检，05 §5.3.6）→ 按 `TimedOut` 处理；其它 handler 生产 Timeout → 记 warning，按 `Internal { message: "handler must not produce Timeout" }` 处理。
2. handler 返回 `Err(Cancelled)` 但 `ctx.cancel_requested() == false` → 记 warning，按 `Internal { message: "Cancelled without cancel flag" }` 处理。
3. 任何 `Err` 都不重试（v1 无显式重试机制；唯一产生新 attempt 的是自环 = 新实例）。
4. 成功返回 `Value` 后，是否发布由调度器按节点类型与门控决定（`end` 不发布，§4.4.2；gate 拦截见 §4.6）。

## 4.2 `NodeContext`

**结论：`NodeContext` 是节点能看到的全部框架能力，由「不可变快照 + 有界可丢通道 + 原子标志」组成；它在类型与所有权上都不可能触达 `RunContext`/`RunState`，因此节点无法破坏调度器不变量。**

### 4.2.1 字段（全私有）

```rust
/// 节点运行时上下文。Clone 廉价：供 Python 代理持有 'static 副本、供 spawn_blocking 闭包捕获。
#[derive(Clone)]
pub struct NodeContext {
    run_id: RunId,                                  // trace/事件归属
    instance_id: InstanceId,                        // 本次执行实例
    node_id: NodeId,                                // 编译图节点
    attempt: Attempt,                               // 0 起，见 00 §0.2
    user_id: String,                                // RunSpec.user_id，只读
    global_vars: Arc<HashMap<String, Value>>,       // 执行开始时的只读快照
    cancel: Arc<AtomicBool>,                        // run 级取消标志（调度器写、节点读）
    stream_tx: mpsc::Sender<TraceEvent>,            // 独立 streaming 通道，cap = STREAMING_CHANNEL_CAP (1024)
    emit_dropped: Arc<AtomicU64>,                   // run 级丢弃计数 → RunFinished.metrics.streaming_dropped
}
```

| 字段 | 来源 | 语义与约束 |
|---|---|---|
| `run_id` / `instance_id` / `node_id` / `attempt` | 调度器 | 只读身份；用于事件、错误定位、日志 |
| `user_id` | `RunSpec.user_id` | 只读；不得回写 |
| `global_vars` | `RunSpec.global_vars` 的**快照**（`Arc`） | 执行开始（Ready→Running）时冻结；v1 无写接口；节点看到的值在一次执行内绝对稳定 |
| `cancel` | `RunState` 共享的 `Arc<AtomicBool>` | 调度器 `store(true)`；节点 `load(Acquire)` |
| `stream_tx` | run 级**独立 streaming 通道**（00 §0.5 `STREAMING_CHANNEL_CAP=1024`；05 §5.8） | **只允许发送 `TraceEvent::Streaming`**；与不可丢 trace 通道物理分离，满即丢 |
| `emit_dropped` | run 级计数器（`RunState` 共享） | `try_send` 失败时 `fetch_add(1, Relaxed)`；每 run 汇总进 `RunFinished.metrics.streaming_dropped`（00 §0.3 `RunMetrics`、03 §3.12）；**不是错误码** |

> **为什么不是 `Arc<RunContext>`**：① 03 的事件循环独占 `&mut RunState`，跨 `'static` 执行任务无法共享可变状态（spike §3.8 已用 channel 回传方案证明）；② 6.1 的隔离承诺要求用户回调"物理上碰不到 RunContext"；③ 节点若能写 buffer/global_vars/状态机，I1–I9 全部失效。因此 `NodeContext` **只有不可变数据与只写通道**。

### 4.2.2 方法（公开 API）

| 方法 | 签名 | 行为 | 失败/边界 |
|---|---|---|---|
| `emit` | `pub fn emit(&self, event: StreamingEvent)` | 构造 `TraceEvent::Streaming { run_id, instance_id, event }`（00 §0.3）后 `try_send` | 通道满 → 丢弃 + `emit_dropped += 1`；通道关闭 → 丢弃 + 计数；**不阻塞、不 panic、无返回值** |
| `get_var` | `pub fn get_var(&self, key: &str) -> Option<&Value>` | 读只读快照 | 键不存在 → `None` |
| `user_id` | `pub fn user_id(&self) -> &str` | 当前用户 ID | — |
| `cancel_requested` | `pub fn cancel_requested(&self) -> bool` | `AtomicBool::load(Acquire)`，快照语义（非同步点） | — |
| `check_cancelled` | `pub fn check_cancelled(&self) -> Result<(), NodeError>` | 已请求取消 → `Err(NodeError::Cancelled)`；否则 `Ok(())` | 供节点在长循环/分片处主动退出 |
| `node_deadline_remaining_ms` | `pub fn node_deadline_remaining_ms(&self) -> u64` | `deadline.saturating_duration_since(now).as_millis() as u64`；已过期 → `0` | 供 Harness 每轮循环前预检（05 §5.3.6）；**不用于代替调度器超时** |
| `cancel_token` | `pub fn cancel_token(&self) -> CancelToken` | 返回可克隆的取消令牌（`CancelToken = Arc<AtomicBool>` 的轻量包装；`is_cancelled()` + `cancelled().await`） | Harness 传给 `LlmProvider` 以中断 HTTP 流（05 §5.3.2） |
| `run_id` / `instance_id` / `node_id` / `attempt` | 同名 getter | 只读身份 | Python 代理**不暴露**（最小面原则） |
| `new` | `pub(crate) fn new(...) -> NodeContext` | **仅 03 派发路径**构造（03 写作 `NodeContext::new(run, inst)`；参数集由 03 定，语义上必须覆盖上表全部字段来源） | 用户代码无法构造 |

**显式禁止的暴露面**（实现审阅检查项）：

| 禁止项 | 原因 |
|---|---|
| `&RunContext` / `&RunState` / 任何调度器句柄 | 破坏隔离与 `&mut` 所有权模型 |
| buffer 写接口、global_vars 写接口 | 唯一数据通道是"output → 边 → input port" |
| 可靠的 trace/transition 通道 | I6 要求 transition 不可丢；节点只允许产生**可丢**的 streaming |
| `spawn`/`subscribe`/gate 求值 API | 节点不得自行调度或影响图拓扑 |
| `NodeContext` 字段 `pub` | 防止绕过 getter 破坏只读语义 |

### 4.2.3 为什么 `emit` 是同步 `fn` 而内部非阻塞

**结论：Python 侧是同步函数、无法 `await`；若 `emit` 走异步/背压，节点延迟将被 trace 消费者绑架。`try_send` 实测 3.86 µs/次且无死锁，是唯一同时满足"跨语言可调用 + 不阻塞 GIL 线程 + 不阻塞事件循环"的方案。**

| 备选 | 结果 | 判定 |
|---|---|---|
| `async fn emit` + `send().await` | Python 无法调用（无 event loop / 无法 await） | ❌ |
| 同步 `send()` 阻塞等待 | 通道满时阻塞持 GIL 的线程 → 事件循环/其它节点被拖死 | ❌ |
| **同步 `fn` + `try_send`** | 10k 次 38.6 ms（3.86 µs/次）；cap=2 时 100 次 → sent 2 / dropped 98，无 panic、无死锁 | ✅ |
| 无界通道 | 内存无上限，trace 消费者停摆时 OOM | ❌（违反 I6 有界设计） |

- 可丢性依据：00 §0.6 I6 —— `Streaming` 可丢且必须计数；`RunStarted`/`Transition`/`GateResult`/**`NodeTimedOut`**/**`NodeAbandoned`**/`RunFinished` 不可丢，而 `NodeContext` **在类型上没有**发送这些事件的通道。
- 容量：`STREAMING_CHANNEL_CAP = 1_024`（00 §0.5，不可配置）。
- 性能预算（spike §3.3）：emit 回调 ≈3.86 µs；**禁止在 `emit` 内做 SQLite 写、日志格式化、加锁**，否则放大 GIL 持有时间。
- 指标：丢弃计数每 run 汇总进 `RunFinished.metrics.streaming_dropped`（03 §3.12、06 落库）；`GateResult`/`Transition` 不受影响。

### 4.2.4 线程与 `Send`/`Sync` 属性

- `NodeContext: Send + Sync`（字段逐项满足：`String`、`Arc<HashMap>`、`Arc<Atomic*>`、`mpsc::Sender`）。
- Python 代理持有 `NodeContext` 的**所有权副本**（Clone），因此满足 PyO3 `#[pyclass]` 的 `'static` 要求（关闭审计 P-05/P-12）。
- `run` 在 `spawn_blocking` 前把 `inputs` 与 `ctx.clone()` 移入闭包；**闭包内不得再跨 `await` 持有 Python token**（spike §4.4）。

## 4.3 Python 节点契约

**结论：Python 节点是一个同步模块级函数 `run(inputs, ctx) -> dict`；输入是"全部声明端口 + 未到为 None"，输出必须是 JSON 对象；所有异常被结构化并保证解释器可继续使用。**

### 4.3.1 函数形态与导入

```python
# myapp/nodes/parse.py   —— DSL 符号（全限定）："myapp.nodes.parse.run"
from zgraph import NodeError          # 业务异常（可选导入）

def run(inputs: dict, ctx) -> dict:
    """同步、模块级、恰好 2 个必填位置参数、无 *args/**kwargs。"""
    ...
```

| 项 | 规定 |
|---|---|
| 符号引用 | DSL 中写**全限定名** `module.function`（如 `myapp.nodes.parse.run`）；模块可含点，最后一段为属性名；符号必须含 `.`（02 分册规则） |
| 导入实现 | `importlib.import_module("myapp.nodes.parse")` + `getattr(mod, "run")`；**不支持嵌套 qualname / 类方法 / `functools.partial`** |
| 函数种类 | 必须 `inspect.isfunction(f) == True`；`async def` 在 v1 **不支持**（§4.3.5 S3） |
| 可用 stdlib | 允许；不得依赖框架事件循环（无 `asyncio` 上下文） |
| 上下文对象 | `zgraph.NodeCtx` 的实例，由框架注入；节点**不得**构造、保存到全局、跨调用复用 |

> Python 包 `zgraph` 由框架随 CLI/bin 提供（模块搜索路径见 `python_path` 全局配置，02/06 定义）。v1 用系统 Python 3.13 + 项目 venv（决策记录-01 §7）。

### 4.3.2 `inputs` 与返回值（字段级）

**`inputs` 构造规则**（由 `PythonNodeHandler` 完成，节点不可协商）：

| 键 | 值 |
|---|---|
| 该节点 DSL 中声明的**每一个** input port | 一定存在（无 KeyError） |
| 未到达的 optional port | `None` |
| `trigger = "any"` 下未到达的 required port | `None`（00 §0.7 / 审计 C-08 裁定：缺失 required 显式注入 null） |
| 已到达端口的值 | 上游 output 的**整包**（§4.5）或 RunSpec 注入值；经 JSON→Python 转换，**新建对象** |
| 额外键 | 不存在（不得出现节点未声明的键） |

- 值的可变性：转换产生新对象，节点就地修改 `inputs` **不影响**框架 buffer 与其它下游（隔离性）。
- 端口类型声明（`string`/`number`/…）在 v1 只做加载期元数据，**不做运行期类型强校验**（02 分册裁定）；节点需自行防御。

**返回值规则**：

| 情形 | 结果 |
|---|---|
| 返回 `dict`（含空 `{}`） | 合法；作为节点 `output` 转成 `Value::Object` |
| 返回 `dict` 子类 | 合法（按 `dict` 转换） |
| 返回非 `dict`（含 `None`/list/str/int） | `NodeError::BusinessError { code: "NODE_RETURN_NOT_DICT", message: "run() must return dict, got <type>" }` → Crashed |
| 键非 `str`、值不可 JSON 化（含 `NaN`/`Infinity`、越界整数、自定义对象） | `NodeError::BusinessError { code: "NODE_RETURN_NOT_JSON", message: … }` → Crashed |
| 转回 Rust 过程中抛异常 | 同 `NODE_RETURN_NOT_JSON`（异常信息进 message） |

> **框架保留业务码（v1 全集，仅 2 个）**：`NODE_RETURN_NOT_DICT`、`NODE_RETURN_NOT_JSON`。它们是 `NodeError::BusinessError.code` 的**载荷值**，不是 00 §0.4 的顶层错误码；用户业务码禁止用 `NODE_` 前缀。
> 整数范围：Python 任意精度 int 仅接受 `i64`/`u64`（及 `f64` 有限浮点）可表示范围（spike §3.1 已验证 i64 精度；越界视为不可 JSON 化）。

### 4.3.3 `ctx` 的 Python 代理（`zgraph.NodeCtx`）

**结论：`ctx` 是「只读代理 + 一个投递方法」；`emit` 的 payload 做严格字段校验，非法即抛 `EmitError`，通道满则静默丢弃并计数——两类失败的成因与处理完全不同，不得混为一谈。**

| 成员 | 形式 | 签名 | 行为 | 失败 |
|---|---|---|---|---|
| `emit` | 方法 | `emit(event: dict) -> None` | 校验后投递 streaming 事件；同步 `try_send`（§4.2.3） | 非法 payload → `zgraph.EmitError`（`ValueError` 子类） |
| `get_var` | 方法 | `get_var(key: str) -> Any \| None` | 读全局变量只读快照；每次返回**新** Python 对象 | 非 `str` key → `TypeError` |
| `user_id` | 只读属性 | `str` | 当前用户 ID | — |
| `cancel_requested` | 只读属性 | `bool` | run 级取消标志快照 | — |
| `check_cancelled` | 方法 | `check_cancelled() -> None` | 已请求取消 → `raise zgraph.Cancelled` | — |
| `run_id` / `instance_id` / `node_id` / `attempt` | **不暴露** | — | 最小暴露面（§4.2.2） | — |

**`emit(event)` 允许的 `type` 与字段校验（权威表）**：

| `event["type"]` | 必填字段 | 可选字段（缺省） | 映射到 `StreamingEvent`（00 §0.3） | 字段校验 |
|---|---|---|---|---|
| `"token"` | `text: str` | — | `TokenDelta { text }` | `text` 必须 `str`（空串允许） |
| `"reasoning"` | `text: str` | — | `ReasoningDelta { text }` | 同上 |
| `"tool_call_start"` | `call_id: str`、`tool_name: str` | `args_summary`（缺省 `{}`） | `ToolCallStart { call_id, tool_name, args_summary }` | `call_id`/`tool_name` 非空 `str`；`args_summary` 必须可 JSON 化 |
| `"tool_call_end"` | `call_id: str`、`tool_name: str`、`ok: bool` | `result_summary`（缺省 `None`） | `ToolCallEnd { call_id, tool_name, ok, result_summary }` | `ok` 严格 `bool`（`type(ok) is bool`，拒绝 `0/1`）；`call_id`/`tool_name` 非空 `str`；`result_summary` 可 JSON 化 |
| `"progress"` | `percent: int`、`message: str` | — | `Progress { percent, message }` | `percent` 严格 `int`（排除 `bool`）且 `0 <= percent <= 100`；`message` 为 `str`（空串允许） |

**校验与失败规则**：

1. `event` 必须是 `dict`；`event["type"]` 必须存在且为 `str`，取值仅上表 5 个之一。
2. 必填字段缺失/类型错、未知 `type` → `EmitError`；**未知额外键忽略**（前向兼容，便于未来加字段）。
3. `EmitError` 是**编程错误**：抛给 Python 调用方（节点可捕获修正）；**未捕获** → 走 `PythonException` → 实例 Crashed（§4.3.4）。**不静默丢弃**。
4. 通道满/已关闭 → **静默丢弃 + `RunMetrics.streaming_dropped` 计数**（容量问题而非错误；I6 允许 Streaming 丢）。
5. proxy 生命周期 = 本次 `run` 调用期间；不得保存到模块全局、不得跨调用复用（框架不保证有效）。
6. `emit` 内部无锁、无 I/O、无 sleep，实测 ≈3.86 µs/次（spike §3.3）；不要在 Python 侧包重试循环。
7. 代理**没有** Transition / GateResult / RunFinished 通道（类型上不存在）——不可丢事件只能由框架产生（I6）。

### 4.3.4 Python 异常 → `NodeError` 映射（权威表）

```python
# 用户可用异常
from zgraph import NodeError, Cancelled
raise NodeError("ORDER_NOT_FOUND", "订单不存在")   # → BusinessError
ctx.check_cancelled()                              # 内部 raise Cancelled
```

| Python 抛出物 | Rust `NodeError` | 实例状态 | trace |
|---|---|---|---|
| `zgraph.NodeError`（业务异常，含 `code: str`、`message: str` 属性） | `BusinessError { code, message }` | Crashed | error；**traceback 记入 log/trace，不进 `NodeError`（结构无此字段）** |
| `zgraph.Cancelled` 且 `ctx.cancel_requested() == true` | `Cancelled` | Cancelled | info |
| `zgraph.Cancelled` 但未请求取消 | `PythonException { message: "unexpected Cancelled: …", traceback }` | Crashed | error |
| 其它 `Exception` 子类 | `PythonException { message: "<TypeName>: <str>", traceback: format_exc() }` | Crashed | error |
| `SystemExit` | `PythonException { message: "SystemExit: <code>", traceback }` | Crashed | error + warning |
| `KeyboardInterrupt` | `PythonException { message: "KeyboardInterrupt", traceback }` | Crashed | error |
| 其它 `BaseException` 子类（`GeneratorExit` 等） | `PythonException` | Crashed | error |

**实现约束**：

1. Rust 侧捕获 `PyErr`（PyO3 对 `Exception` 与 `BaseException` 都返回 `Err`），**不得 `panic!`、不得 `PyErr::restore` 后再抛**；捕获后异常上下文清空，解释器可继续执行（spike §3.5：连续 3 轮失败后 `sys.exc_info()` 干净）。
2. 自定义业务异常的 `code` 需主动从 `err.value(py)` 取属性（PyO3 默认不携带自定义属性，spike §3.5）。
3. `SystemExit` 被捕获后**不允许**导致进程退出——它只是普通 `PyErr`，绝不传播到 Rust 顶层。
4. `traceback` 用 `traceback.format_exc()` 全量文本；落库截断策略归 06，本分册不设上限。
5. v1 不使用 `PyErr_SetInterrupt`/signal 取消（spike §3.7 实测无效且产生 "Signal 2 ignored" 噪声）；`KeyboardInterrupt` 出现即视为用户代码主动抛出。

### 4.3.5 签名校验规则（加载期，`inspect.signature`）

**结论：强制校验"可调用性 + 函数种类 + arity/变参"，类型注解只告警不阻断；错误码 `DSL_SIGNATURE_MISMATCH`，解析算法如下。**

| # | 检查 | 通过条件 | 失败 |
|---|---|---|---|
| S1 | 可解析 | `importlib.import_module(module)` 成功且 `getattr(module, attr)` 存在 | `DSL_SYMBOL_NOT_FOUND`（02 §2.5） |
| S2 | 模块级函数 | `inspect.isfunction(f) == True` 且非 class / bound method / partial / 内建 | `DSL_SIGNATURE_MISMATCH`（`expected: "module-level function"`） |
| S3 | 同步 | `inspect.iscoroutinefunction(f) == False`（v1 不支持 `async def`） | `DSL_SIGNATURE_MISMATCH`（`expected: "sync def"`） |
| S4 | 参数个数 | 恰好 **2** 个参数，且均为 `POSITIONAL_ONLY` 或 `POSITIONAL_OR_KEYWORD` | `DSL_SIGNATURE_MISMATCH`（`expected: "(inputs, ctx)"`） |
| S5 | 无变参/无默认值/无 keyword-only | 无 `VAR_POSITIONAL`、无 `VAR_KEYWORD`、无 `KEYWORD_ONLY`；两个参数**均无默认值**（`param.default is empty`） | `DSL_SIGNATURE_MISMATCH`（`actual: str(inspect.signature(f))`） |
| S6 | 返回注解 | **可选**：缺失 → 加载期 warning（不阻断）；存在但非 `dict`/`bool`（规范化后比较）→ warning（不阻断） | 仅 warning，不产生错误码 |
| S7 | 运行期强制 | 返回类型在**每次执行时**强制（节点 `dict` / gate 严格 `bool`） | §4.3.2 / §4.6.2 |

- **参数名不校验**：框架以位置参数调用 `f(inputs, ctx)`；名字用 `inputs, ctx` 仅为约定。
- **为什么注解不阻断**（关闭审计 P-10）：注解在 `from __future__ import annotations` 下是字符串、`typing.Dict` 与 `dict` 不等价、装饰器可改写 `__signature__`——按注解硬比较会把合法函数判错（v1.1 文档写法"所有合法函数都会失败"）。arity 可由签名静态判定、返回类型已由运行期兜底，两者组合覆盖了真实风险。
- **与 02 分册的对应**：本表 S2–S5 的失败统一映射 `DSL_SIGNATURE_MISMATCH`；`expected`/`actual`/`symbol`/`kind`/`location` 的 JSON 结构与错误信息格式由 **02 §2.5** 定义，本分册只固定上述判定算法与字段语义。
- gate 使用同一算法（`SignatureKind::Gate`，`expected: "(output, ctx)"`）。
- 校验执行位置：**加载期、`spawn_blocking` 线程内**（import + `inspect` 都是同步 Python 调用，禁止在事件循环任务内执行，见 00 §0.6 I8）。

### 4.3.6 Python 执行模型约束

**结论：Python 调用一律 `spawn_blocking`，受独立信号量限流；CPU 型节点吞吐 ≈1 核，超时只能"停止等待"；这些不是实现建议，而是验收断言。**

| 约束 | 规定 | 证据/依据 |
|---|---|---|
| 线程模型 | 所有 Python 调用（节点 `run`、gate、import、`inspect`）**必须**在 `tokio::task::spawn_blocking` 内执行；事件循环任务内**禁止**任何同步 Python 调用 | 00 §0.6 I8；spike §3.2：`tokio::spawn` 内直调让 ticker 停顿 405–1502 ms，`spawn_blocking` 后 6–8 ms |
| `run` 内部写法 | `PythonNodeHandler::run` 在 async 函数内 `permit = semaphore.clone().acquire_owned().await` → `spawn_blocking(move || { Python::attach(|py| python_call(py, inputs, ctx.clone())) }).await` | spike §4.1 推荐骨架 |
| 并发信号量 | CPU 型：`PYTHON_CONCURRENCY_CPU = 1`；I/O 型：`PYTHON_CONCURRENCY_IO = 4`（00 §0.5，全局可配）；gate 求值固定占 **CPU** 信号量 | GIL：CPU 型 4 并发墙钟 ≈4×（1.6 s）；I/O 型（sleep）≈1×（0.4 s）（spike §3.2） |
| 类别来源 | `GraphNode.config.exec_class: "cpu" \| "io"`，**缺省 `"io"`**（`PYTHON_EXEC_CLASS_DEFAULT`，00 §0.5；02 §2.2.1 已定义该字段）。契约侧只固定 trait 方法 `python_exec_class()` 与信号量选择规则 | §4.1.1；00 §0.5；02 §2.2.1 |
| 与 tokio worker 解耦 | 不得用 tokio worker 数当 Python 并发度；`spawn_blocking` 线程池容量须 ≥ 两个信号量之和（默认 ≥5） | spike §3.2 结论 3 |
| 超时 | 只实现 **stop-waiting**：到 deadline 记 `NODE_TIMEOUT`、实例 `TimedOut`、run `Failed`；被放弃的 Python 任务**继续运行**直到自然结束，可能继续占 GIL/线程，记 `NODE_ABANDONED` 告警（00 §0.4） | spike §3.7：103 ms 判定超时，任务 `done=false`；drop runtime 需 1890 ms |
| 取消 | 协作式：`ctx.cancel_requested` / `ctx.check_cancelled()`；不保证终止已进入的 C 阻塞调用。**禁止** `PyErr_SetInterrupt`；v1 **不使用** `PyThreadState_SetAsyncExc`（unsafe，可留不一致状态） | spike §3.7（c）；00 §0.6 I8 |
| 解释器 | 单解释器、进程启动时 `Python::initialize()` 一次（在主线程、任何 run 之前）；不支持 sub-interpreter / free-threaded 3.13t | spike §1/§4.4 |
| 解释器与路径注入（N-02） | 解释器：CLI `--python <exe>` > 环境变量 `PYO3_PYTHON` > `python3`；模块搜索路径：CLI `--python-path <dir>`（可重复）按顺序 + 环境变量 `PYTHONPATH`，在 `Python::initialize()` 后、首次 import 前注入一次；禁止运行期修改 `sys.path` | 06 §6.10.2/§6.10.3；决策记录 §7.3 |
| 异常恢复 | 每次失败后解释器必须可继续执行（验收断言，见 07 分册） | spike §3.5 |

**性能预期（写入验收基线）**：Python 节点吞吐 ≈1 核（CPU 型）；并行分支只对 GIL 释放型工作有效；emit ≈3.86 µs/次；10k streaming 事件管道 ≈38.6 ms。

## 4.4 内置节点

**结论：`start` 只做整包透传、`end` 只做聚合且不发布、`subgraph` 在派发前被拒绝；三者都没有业务逻辑。**

### 4.4.1 映射总表

| `NodeType` | 输入来源 | 是否发布 | 输出去向 | 特殊规则 |
|---|---|---|---|---|
| `Start` | `RunSpec.entry_inputs[node_id]`（不经 buffer） | 是（整包广播） | 出边 `to_input_port` | 无入边；不补 null（§4.4.2） |
| `End` | 正常 buffer 聚合（含 null 补齐） | **否** | `RunState.run_output`（浅合并，01 §1.9） | 无出边；不触发 gate |
| `PythonNode` | 正常 buffer 聚合 | 是 | 出边（经 gate） | §4.3 |
| `AgentCall` | 正常 buffer 聚合 | 是 | 出边（经 gate） | 05 分册 |
| `Subgraph` | — | — | — | v1 运行期拒绝（§4.4.4） |

### 4.4.2 `start`

| 项 | 规定 |
|---|---|
| 角色 | 数据流源：把 run 级输入注入图内，无上游 |
| 端口 | `start` 节点**不得**有入边（02 校验）；其 `inputs` 声明即"run 输入契约" |
| 注入校验 | entry 集合与 `entry_inputs` 的一致性由 run 启动阶段校验：`RUN_ENTRY_INVALID`（entry 不存在/多余节点或端口）、`RUN_ENTRY_INPUT_MISSING`（required 未覆盖）→ **不产生 run**（00 §0.4、03）；handler 内不重复校验 |
| 实例创建 | run 启动时由 03 创建；**不经过 buffer 就绪判定**，直接 `Pending → Ready → Running` |
| `inputs` 构造 | 直接取 `RunSpec.entry_inputs[start_node_id]`（`HashMap<PortName, Value>`）**原样**；不补齐未注入的声明端口（`start` 是源，不是汇聚点）。未提供注入 → 空 map |
| handler 行为 | 唯一动作：`Ok(Value::Object(inputs))`；不做业务逻辑、不做类型转换、不 emit |
| 空注入 | 输出 `{}`（合法；是否应报错由 06 CLI 的 `--inputs` 校验决定，不在 handler 内） |
| 多 start | `entry_points` 可含多个 start，各自独立注入、各自广播 |

### 4.4.3 `end`

| 项 | 规定 |
|---|---|
| 角色 | 汇聚终点：把分支结果汇成 `RunState.run_output`；**不产生下游投递** |
| 端口/边 | `end` 不得有出边（02 校验）；必须声明至少一个 input（02 规则，用于接收结果） |
| `inputs` 构造 | 与普通节点一致：全部声明端口、未到为 `Value::Null` |
| handler 输出 | `Ok(Value::Object(inputs))`（即"端口名 → 值"的对象） |
| 是否发布 | **否**。调度器按 `NodeType::End` 跳过 publish 与 gate；end 节点上不存在门控求值 |
| `run_output` 组装 | 单 end：`RunState.run_output = end.inputs`（`{}` 若空）。多 end：按 `CompiledGraph.node_order`（即 DSL `nodes` 数组顺序）对已完成 end 的 inputs 做**顶层浅合并**，同名键后者覆盖前者，冲突记 warning（01 §1.9） |
| 无输入 | 实例 `inputs` 为空 map（未声明端口）→ 输出 `{}`；不影响合并 |
| 失败/取消 | run `Failed`/`Cancelled` 时 `run_output = null`（`None`），不聚合未完成 end |
| 无 end 执行（全部 Skipped） | `run_output = null`；run 仍可 `Completed`（设计者主动门控掉整条链，01 §1.9） |
| 无 end 节点 | 图可无 end（02 允许时）→ 静默完成时 `run_output = null` |

> `run_output` 的内存位置（`RunState.run_output: Option<Value>`）、落库（`runs.output_json`）与 CLI 展示（`RunFinished.output_summary`）归 01/06；本分册只固定**组装语义**。

### 4.4.4 `subgraph`（v1 只校验、不执行）

| 阶段 | 行为 | 依据 |
|---|---|---|
| 图加载期 | 子图定义（`subgraphs` 数组）与引用**正常校验并通过**（`DSL_SUBGRAPH_INVALID` 只针对定义非法）；`NodeType::Subgraph` 节点被编译进图 | 02 分册裁定；决策记录-01 §2.2 |
| 运行期（派发前） | 调度器在"就绪 → 派发"处检测 `NodeType::Subgraph`：**不创建实例、不构造 handler、不执行**；run 立即 `Failed`，错误码 `NODE_TYPE_UNSUPPORTED`（00 §0.4 运行期域），其余非终态实例转 `Cancelled` | 00 §0.3 注释、§0.4；I9 |
| trace | 记 error：`node_id`、`instance_id = null`（未创建），message 指明 `subgraph execution is not supported in v1` | 06 |
| 为什么不在加载期拒绝 | 保留 DSL 定义与校验能力（v1.1 将启用执行），加载失败会掩盖其余图错误；"能加载、不能跑"是 v1 的显式语义 | 决策记录-01 D1/§2.2 |
| v1.1 切换 | 新增 `SubgraphHandler` 后移除该派发前检查；DSL 无需变更 | §4.8 |

## 4.5 输出路由（v1：整包广播）

**结论：节点输出是一个「整体」`Value`，不做字段级拆分；每条出边都收到同一份不可变值并写入目标端口，下游节点自己从对象里取字段。**

### 4.5.1 语义（精确描述）

1. 节点成功返回 `output: Value`（通常为 object，但 v1 **不强制** object；非 object 也按整包分发）。
2. **两阶段（01 §1.4）**：执行任务在回传 `NodeCompleted` 前，off-loop 对该节点每条出边求值 gate，结果以 `GateEvaluation` 回传（§4.6.1）；事件循环的 `publish()` 只做**纯寻址/组装**，**不调用 Python**。
3. `publish()` 遍历该节点的全部出边（按 `EdgeIndex` 升序）并生成 `PublishResult`：
   - 已求值 `passed == false` → 产生 `BlockedDelivery`（不产生 Delivery，用于结算入边与 Skipped 级联）；
   - `passed == true`（或该边无 gate）→ 产生 `Delivery { edge_index, to_instance, to_port, data, gate: Option<GateOutcome>, .. }`（字段见 01 §1.4），其中 `data` **就是整个 `output`**（逻辑副本；实现可用 `Arc<Value>` 共享，语义不可变）。
4. 事件循环统一应用 `PublishResult`：Delivery → 写 buffer + 结算入边 + 就绪判定；下游 `inputs[to_port] = 整个 output`（**不是** `output[字段]`）。
5. 不变式：每条边单次 publish 至多一个 Delivery（00 §0.6 I4）；同一份 output 在所有边上语义相同（广播）。
6. `end` 节点不 publish（§4.4.3）；因此 `end` 的出边在 DSL 中非法（02 校验）；`end` 上不进行 gate 求值。

### 4.5.2 为什么 v1 选择整包广播

| 维度 | 整包广播（选） | 字段级路由（v2） |
|---|---|---|
| DSL 现状 | `GraphNode` 无 `outputs` 声明（00 §0.2/02） | 需新增 `outputs[]` + `from_output_port` |
| 语义确定性 | 下游明确知道拿到的是上游完整结果，取字段责任在节点 | 端口语义更强，但需校验"声明的输出端口与运行时字段一致" |
| 框架复杂度 | publish 纯函数，无字段存在性判定 | 需字段缺失策略、端口类型校验 |
| 示例修正成本 | 只需修正 5.3 示例（本分册已修正） | 需改 DSL、编译产物、Delivery |
| 结论 | v1 采用；`outputs` 作为**保留字段**只校验不路由 | v2 启用（§4.5.4） |

### 4.5.3 正确示例（修正 v1.1 §5.3 的错误写法）

> v1.1 §5.3 的 `inputs["user_query"]` 注释为"对应数据"，暗示端口收到的是字段值本身——这与整包广播矛盾（审计 M-16）。**正确语义：端口收到上游整个 output 对象，节点自行取字段。**

```python
# 上游节点 answer_generator 的 output：{"answer": "...", "confidence": 0.83}
# 边：answer_generator → human_escalation_check，to_input_port = "answer"
#     answer_generator → end_success，           to_input_port = "result"
def run(inputs: dict, ctx) -> dict:
    # ① 端口 "answer" 收到的是上游「整个 output 对象」
    upstream = inputs["answer"]
    if not isinstance(upstream, dict):
        raise NodeError("BAD_UPSTREAM", "answer port expects the whole upstream output object")

    # ② 节点自己取字段（字段缺失时由节点决定兜底策略；v1 无框架级字段路由）
    answer = upstream.get("answer", "")
    confidence = float(upstream.get("confidence", 0.0))

    # ③ 未到达的 optional 端口 = None（显式存在，不用 .get 也不会 KeyError）
    history = inputs["history"]
    history = history if history is not None else []

    # ④ emit 是同步调用；非法 payload 抛 zgraph.EmitError（编程错误，不静默丢）
    ctx.emit({"type": "progress", "percent": 10, "message": "开始评估"})

    # ⑤ 协作取消：长循环/分片处自检
    ctx.check_cancelled()

    ctx.emit({"type": "progress", "percent": 100, "message": "完成"})
    return {"need_human": confidence < 0.5, "answer": answer, "history_len": len(history)}
```

下游 `end_success` 的 `inputs["result"]` 同样是**整个 object**（`{"need_human": ..., "answer": ..., "history_len": ...}`），其输出对象进入 `RunState.run_output`（01 §1.9）。

### 4.5.4 v2 预留：`from_output_port`（不实现）

| 项 | v1 行为 | v2 语义（预留，不实现） |
|---|---|---|
| `GraphNode.outputs?: OutputPort[]` | 02 保留字段；v1 若存在，仅校验其与下游 `from_output_port` 引用一致，**不参与路由** | 节点声明输出端口，端口名参与路由与类型校验 |
| `GraphEdge.from_output_port?: string` | **必须缺省**；出现即由图加载拒绝：`DSL_UNSUPPORTED_FIELD`（00 §0.4 / 02 §2.6），**不得静默忽略** | publish 时取 `output[from_output_port]` 投递；字段缺失 → 投递 `null` 并记 warning |
| `Delivery.data` | 整个 output | 被选端口的值 |

> v2 也不引入"多输出节点"的并行语义：仍是一条边对应一个值，只是取值的键不同。

## 4.6 门控契约（`GateContext`）

**结论：gate 是"边上的纯函数过滤器"，输入 `(output, GateContext)`、输出严格 `bool`；它只决定这条边是否投递，不改变数据、不改变 run 状态、不能发事件。**

### 4.6.1 签名与求值时机

```python
# DSL 边上的 gate 符号（全限定名，如 "gates.hr.need_human"）
def gate(output, ctx) -> bool:
    ...
```

| 项 | 规定 |
|---|---|
| 符号引用 | `GateDefinition.function` = 全限定 `module.function`（02 §2.5；关闭审计 C-22） |
| 参数 | 恰好 2 个必填位置参数 `(output, ctx)`；同步模块级函数；无 `*args/**kwargs`（§4.3.5 同算法） |
| `output` | **发布者节点的原始 output**（只读逻辑副本；整包，§4.5） |
| `ctx` | `GateContext`（Rust）/ `zgraph.GateCtx`（Python），见 §4.6.3 |
| 求值者 | **发布者实例的执行任务**（executor，off-loop）：handler 返回后、回传 `NodeCompleted` 前求值；每条**声明了 gate 的出边**求值一次（01 §1.4、03 §3.3） |
| 求值顺序 | 按 `EdgeIndex` 升序；同一 gate 函数被多条边引用 → **每条边各求值一次**（gate 必须无副作用，否则顺序可观察） |
| 数据影响 | **无**：gate 不能修改/转换 payload；publish 始终使用原始 output（推翻 v1.1 §2.4.4「gate 转换后的值」） |
| 状态影响 | **无**：拦截只导致该边无 Delivery（记 `BlockedDelivery`）；不使实例 Crashed、不使 run Failed（I7） |
| 并发/线程 | 执行任务内 `spawn_blocking` + **CPU** Python 信号量；事件循环线程**不**调用 Python（I8）。求值结果以 `GateEvaluation` 随 `NodeCompleted` 回传（01 §1.7） |
| 超时 | v1 不设 gate 独立超时；gate 求值发生在实例 `Running` 期间，受**实例级 timeout**（节点 `timeout_ms` / `DEFAULT_NODE_TIMEOUT_MS`）覆盖：超时按 `NODE_TIMEOUT` 处理（03 §3.9）。gate 仍须快速、无 I/O、无阻塞 |
| 拦截后的下游 | 该边无数据；下游实例可能永不就绪 → 由 03 判定 `Skipped`（入边全部被拦截）/`RUN_DEADLOCK` |

### 4.6.2 严格 `bool` 规则（权威）

**只接受 Python `bool`。`int`/`str`/`None`/其它可 `__bool__` 对象一律视为返回类型错误：拦截 + warning + trace，不使 run Failed。**

| gate 返回 | 判定 | `passed` | 记录 |
|---|---|---|---|
| `True` / `False`（`type(x) is bool`） | 合法 | 对应值 | `GateResultRecord{passed, error: None}` |
| `1` / `0`（`int`） | 类型错误 | `false`（拦截） | warning + `GateResultRecord{passed:false, error:"return_type: int"}` |
| `"yes"` / `"false"`（`str`） | 类型错误 | `false` | error 同上（`str`） |
| `None` | 类型错误 | `false` | error 同上（`NoneType`） |
| 自定义 `__bool__` / `numpy.bool_` | 类型错误 | `false` | error 同上（类型名） |
| 抛 Python 异常 | 求值失败 | `false` | warning + `error:"exception: <Type>: <msg>"`（traceback 摘要入 log） |
| Rust 侧 panic（理论上不应发生） | 求值失败 | `false` | warning + `error:"panic"` |

**为什么严格（裁定理由）**：

1. **类型系统一致性**：spike §3.4 实测 PyO3 `extract::<bool>()` 对 `str`/`int`/`None` 直接 `TypeError`；若声明 `-> bool` 又在运行期接受 truthiness，等于实现与声明不符（v1.1 文档的问题）。
2. **拓扑安全性**：truthiness 会把 `"false"`（非空字符串）判为 `True`，静默走错分支——图的路由错误无法在 trace 中发现；严格模式把错误显式化。
3. **前向兼容**：宽容语义若日后要收紧就是破坏性变更；严格语义可以日后通过显式 opt-in（v2 `@gate(truthiness=True)`）放宽。
4. **失败安全**：错误必须表现为"不通过"（I7 异常/panic = 不通过），而不是"通过"或"run 失败"。gate 类型错误是**图配置错误**，不是节点业务失败；把它升级为 run Failed 会让一个过滤条件错误摧毁整次执行。

> 运行期强制是唯一可靠的判定点：Python 无静态类型，加载期无法验证返回值类型。

### 4.6.3 `GateContext`（Rust）与 Python 代理

```rust
/// 门控只读上下文。无 emit、无 cancel、无 run 状态；构造器仅框架内可用。
#[derive(Clone)]
pub struct GateContext {
    run_id: RunId,
    user_id: String,
    global_vars: Arc<HashMap<String, Value>>,
    params: Value,                     // GateDefinition.params，缺省 {}（02 §2.9.3）；Python 侧为 dict
}

impl GateContext {
    pub(crate) fn new(
        run_id: RunId,
        user_id: String,
        global_vars: Arc<HashMap<String, Value>>,
        params: Value,
    ) -> Self;

    pub fn user_id(&self) -> &str;
    pub fn get_var(&self, key: &str) -> Option<&Value>;
    pub fn params(&self) -> &Value;
    pub fn run_id(&self) -> &RunId;   // 仅日志/定位，不暴露给 Python
}
```

| 能力 | Rust | Python 代理 `zgraph.GateCtx` | 说明 |
|---|---|---|---|
| 用户身份 | `ctx.user_id()` | `ctx.user_id`（属性，`str`） | 只读 |
| 全局变量 | `ctx.get_var(key)` | `ctx.get_var(key)` | 只读快照；缺失返回 `None`；每次返回**新** Python 对象（防止改动快照） |
| 门控参数 | `ctx.params()` | `ctx.params`（属性） | `GateDefinition.params` 的 JSON→Python 转换；缺省 `{}` → Python `dict`（02 §2.9.3 统一） |
| emit | **无** | **无** | I7：gate 不发事件 |
| 取消标志 | **无** | **无** | gate 是短时纯函数，不做协作取消 |
| run 状态/buffer/实例表 | **无** | **无** | 隔离承诺（原 6.1） |

- **构造时机**：由发布者实例的**执行任务**在 handler 返回后、回传 `NodeCompleted` 前构造；事件循环线程不构造、不调用 Python（01 §1.4、03 §3.3）。
- `params` 与 `global_vars` 都是**每次求值时**从编译产物/RunSpec 快照传入，gate 不可写。
- 同一 gate 的多条边：每条边各自构造 `GateContext`（携带该边 `GateDefinition.params`）。

### 4.6.4 `GateResultRecord`（trace 事件载荷）

**结论：每条带 gate 的边求值必产生一条 `GateResult`（I6 不可丢）；字段用于回放判断与排障。**

```rust
/// 字段权威定义在 01 §1.5；本分册逐字对齐，不另立字段。
/// trace 事件外壳为 00 §0.3 `TraceEvent::GateResult { record }`。
pub struct GateResultRecord {
    pub run_id: RunId,
    pub instance_id: InstanceId,     // 发布者实例
    pub node_id: NodeId,             // 发布者节点
    pub edge_index: EdgeIndex,       // 被求值的边（与 DSL edges 数组下标一致）
    pub to_node: NodeId,             // 该边目标节点
    pub to_port: PortName,           // 该边目标端口
    pub gate_fn: Option<String>,     // None = 该边无 gate（恒真）
    pub passed: bool,                // 唯一的路由判据
    pub error: Option<String>,       // 仅类型错误/异常/panic 时有值；合法 False 返回为 None
    pub ts: DateTime<Utc>,
}
```

| 字段 | 必有 | 说明 |
|---|---|---|
| `run_id` / `instance_id` / `node_id` | 是 | run 与发布者定位 |
| `edge_index` / `to_node` / `to_port` | 是 | 边与目标端口定位（边数据从 `CompiledGraph.edges[edge_index]` 取，01 §1.2） |
| `gate_fn` | 是 | 全限定符号；`None` 表示该边无 gate（恒放行） |
| `passed` | 是 | 与路由完全一致（trace 可回放） |
| `error` | 否 | 结构化前缀便于断言：`return_type:` / `exception:` / `panic` |
| `ts` | 是 | 求值时刻 |

- 回传载体：执行任务用 01 §1.7 的 `GateEvaluation { edge_index, passed, error }` 随 `NodeCompleted` 回传；事件循环据此**物化**为 `GateResultRecord` 并 `send().await` 落 trace（不可丢，I6）。
- **不记录求值耗时**：01 的记录无 `elapsed_ms`，本分册不新增字段；若需 gate 性能指标，由 06 从 executor 侧另行计时，不得改 `GateResultRecord`。

### 4.6.5 加载期与运行期分工

| 阶段 | 检查 | 失败 |
|---|---|---|
| 加载期（§4.7） | 符号可导入、模块级同步函数、arity=2、无变参 | `DSL_SYMBOL_NOT_FOUND` / `DSL_SIGNATURE_MISMATCH` |
| 运行期（每次求值） | 返回值严格 bool；异常/panic 捕获 | 拦截 + warning + `GateResultRecord` |
| 定位信息 | 加载期带 `symbol` + `edge_index`；运行期带 `edge_index` + `gate_fn` + `instance_id` | — |

## 4.7 `SymbolResolver`

**结论：DSL 里的字符串符号在「加载期」一次性解析为不可变可调用对象（`Arc`），运行期只查表不解析；注册表进程级、幂等复用，换图不影响已启动的 run。**

### 4.7.1 注册表结构

```rust
/// 符号种类（三类注册表，key = 全限定名 module.function）
pub enum SymbolKind { Gate, Node, Skill }

pub struct SymbolResolver {
    gates: HashMap<String, Arc<RegisteredFn>>,   // key = "gates.hr.need_human"
    nodes: HashMap<String, Arc<RegisteredFn>>,   // key = "myapp.nodes.parse.run"
    skills: HashMap<String, Arc<RegisteredSkill>>, // ToolDef 由 05 分册定义
}

pub struct RegisteredFn {
    pub symbol: String,          // 全限定名（唯一键）
    pub kind: SymbolKind,        // Gate | Node（Skill 不走此结构）
    pub func: Py<PyAny>,         // 已 import 的模块级函数对象（importlib 缓存持有）
    pub signature: SignatureInfo,
}

pub struct SignatureInfo {
    pub positional_required: u8,        // 必须 == 2
    pub accepts_varargs: bool,          // 必须 false
    pub accepts_kwargs: bool,           // 必须 false
    pub is_coroutine: bool,             // 必须 false
    pub return_annotation: Option<String>, // 仅用于 warning 文案
}

impl RegisteredFn {
    /// 唯一调用入口；必须持有 GIL token（关闭审计 P-11）。
    /// 调用方：PythonNodeHandler / GateEvaluator，且仅在 spawn_blocking 线程内。
    pub(crate) fn call(
        &self,
        py: Python<'_>,
        args: &[&Value],
    ) -> Result<Value, PythonCallError>;   // 内部完成 Value→PyObject→调用→PyObject→Value
}

/// 解析产物快照：node_id → 绑定对象；由 run 持有，运行期 O(1) 查表，不再访问 resolver。
pub struct ResolvedSymbols {
    pub by_node: HashMap<NodeId, Arc<RegisteredFn>>,
    pub by_gate_edge: HashMap<EdgeIndex, Arc<RegisteredFn>>,
    pub skills: HashMap<String, Arc<RegisteredSkill>>,
}
```

| 约束 | 规定 |
|---|---|
| key 规范 | 全限定 `module.function`（模块可含点，最后一段为属性名）；解析用 `importlib.import_module(module)` + `getattr`；**不拼接前缀、不做短名补全**（关闭审计 C-22） |
| 不可变性 | `RegisteredFn` 构造后不可变；所有共享用 `Arc`；运行期无 `&mut` registry |
| 线程安全 | resolver 由 Loader 单线程持有（`&mut`）；解析完成后产出 `ResolvedSymbols` 快照交给 run；解析与执行不共享可变状态 |
| 生命周期 | 注册表进程级存活；随进程退出释放；Python 模块缓存（`sys.modules`）同样进程级 |
| skill | `ToolDef` 与工具执行由 05 分册定义；本分册固定"key = 全限定名 + 加载期解析 + Arc 快照"三点 |

### 4.7.2 `resolve_graph` 流程

```rust
impl SymbolResolver {
    /// 图加载期调用一次；失败即图加载失败（不产生 run）。
    /// 必须在 spawn_blocking 线程内执行（import/inspect 都是同步 Python 调用，I8）。
    pub(crate) fn resolve_graph(&mut self, graph: &CompiledGraph)
        -> Result<ResolvedSymbols, DslError>;
}
```

| 步骤 | 动作 | 失败 |
|---|---|---|
| R1 | 按**确定性顺序**收集符号：① 节点数组顺序中的 `python_node` 符号；② 各节点出边按 `EdgeIndex` 升序的 gate 符号。**skill 符号不在图加载期解析**——由 05 的 Harness 在 Agent 载入时懒解析（`HARNESS_CONFIG_LOAD`/`HARNESS_UNKNOWN_TOOL`），图加载期只校验 `agent_id` 资产存在（`DSL_AGENT_NOT_FOUND`） | — |
| R2 | 三类符号分别查表：命中 → 复用（不 import、不校验，幂等） | — |
| R3 | 未命中 → `importlib` 导入 + `getattr` | `DSL_SYMBOL_NOT_FOUND`（含 `symbol`、`module`、原因） |
| R4 | 签名校验（§4.3.5 S2–S5） | `DSL_SIGNATURE_MISMATCH`（含 `symbol`、`kind`、`expected`、`actual`） |
| R5 | 跨类别冲突检测：同一全限定名已存在于**另一类**注册表 | `DSL_SYMBOL_CONFLICT`（含 `symbol`、`existing_kind`、`requested_kind`） |
| R6 | 注册（`Arc<RegisteredFn>`） | — |
| R7 | 产出 `ResolvedSymbols` 快照（按 `NodeId` / `EdgeIndex` / skill 名索引） | — |

- **失败聚合**：加载期遇到首个错误即返回（顺序由 R1 固定，保证同一坏图总是报同一处）；多错误聚合策略归 02。
- **定位字段**（供 02 的错误响应结构使用）：`symbol`、`kind`、`node_id`（节点引用时）、`edge_index`（gate 引用时）、`expected`、`actual`、`message`。
- **时机**：符号解析发生在 Loader 的最后一步（02 §2.5 定义其与 **R1–R14 共 14 条校验**的顺序关系）；与执行期**彻底分离**——运行期不再调用 `resolve_*`。

### 4.7.3 幂等、冲突与热更新边界

| 场景 | v1 行为 | 说明 |
|---|---|---|
| 换图（新 run） | 重新 `resolve_graph`；新符号 import 注册，已注册符号复用 | 每次 run 编译新图，代价 = 一次编译 + 解析；**零重启** |
| 两个图共用同一符号 | 幂等复用同一 `Arc<RegisteredFn>`（先注册者生效） | 同 kind 同名 = 同一实体 |
| 改 Python 代码 | **不生效**（需重启进程） | `sys.modules` 与 registry 双层缓冲；v1 明确不做隐式 reload（安全性 > 便利性） |
| 运行中的 run | 持有 `ResolvedSymbols` 快照，**不受**后续换图/解析影响 | "旧 run 跑旧实现"，物理隔离于 `Arc` 快照 |
| 符号改名/删除 | 新图解析失败 `DSL_SYMBOL_NOT_FOUND`；旧 run 不受影响 | 图级热拔插 = 解除引用，非删除实体 |
| 同名**跨类别**（同一名字既是 gate 又是 node） | `DSL_SYMBOL_CONFLICT`，加载失败 | v1 唯一可达的冲突场景；错误信息提示使用命名空间 |
| 同名不同实现（同类别） | v1 **不会发生**：registry 命中即复用、不重新导入；这是 v1 的**已知限制**，不是静默冲突 | 若将来支持 v1.1 "显式 reload"，才需要实现对象身份比较 |
| 进程内运行时热替换（执行中 swap 实现） | **不支持** | 正在跑的实例已绑定 `Arc`，跑完旧实现；新 run 用新实现 |

### 4.7.4 错误码与定位汇总

| 错误码 | 触发 | 阶段 | 定位信息 |
|---|---|---|---|
| `DSL_SYMBOL_NOT_FOUND` | 模块导入失败 / 属性不存在 / 非模块级函数 | 加载期 | `symbol`、`module`、`node_id`/`edge_index` |
| `DSL_SIGNATURE_MISMATCH` | arity/变参/async/非函数（§4.3.5 S2–S5） | 加载期 | `symbol`、`kind`、`expected`、`actual` |
| `DSL_SYMBOL_CONFLICT` | 同一全限定名跨 gate/node/skill 类别 | 加载期 | `symbol`、`existing_kind`、`requested_kind` |
| `DSL_AGENT_NOT_FOUND` | `agent_call.agent_id` 资产缺失（05 资产加载） | 加载期 | `agent_id`、`node_id` |
| `NODE_TYPE_UNSUPPORTED` | 运行到 `subgraph` 节点 | 运行期（派发前） | `node_id` |

> 错误响应 JSON 的结构、`expected/actual` 文案格式、CLI 输出由 02 分册统一；本表只固定触发条件与必须携带的定位字段。

## 4.8 扩展点边界（v1 固定 vs 用户提供）与后续扩展位

**结论：框架固定「调度/发布/门控求值/超时」，用户只提供「函数体 + 数据资产」；v1.1/v2 的扩展全部通过新增类型/子 trait 落地，不修改本分册的 v1 签名。**

### 4.8.1 边界表

| 对象 | 框架固定（用户不可改） | 用户提供（框架不可知） |
|---|---|---|
| 节点 | 就绪判断、状态机、调度、发布/扇出、超时/panic 捕获、trace、并发限流 | `run(inputs, ctx) -> dict` 函数体、节点 `config`（module/function 等） |
| 门控 | 求值时机（发布者 publish 阶段）、每条边一次、拦截语义、严格 bool、异常=拦截 | `gate(output, ctx) -> bool` 函数体、`params` |
| Skill | 工具调用协议、执行器、ToolDef 契约（05） | 工具实现 + ToolDef 声明（05） |
| Agent | 六阶段循环、上下文预算、错误映射（05） | AgentConfig 资产、prompt 文件、tools 列表 |
| 符号解析 | 注册表、全限定命名、加载期解析、冲突检测 | Python 模块路径/函数名（通过 DSL 声明） |

**隔离机制（三条）**：① 注册表（用户代码经解析进入，不改框架代码）；② 契约（trait/函数签名，框架只依赖契约）；③ 受限 ctx（`NodeContext`/`GateContext` 不暴露 `RunContext`）。

### 4.8.2 后续扩展位（v1 不实现，只登记）

| 扩展位 | 版本 | 落地方式（不破坏 v1） | 本分册影响 |
|---|---|---|---|
| 人工介入 / 恢复 | v1.1 | 新增 `ResumableNodeHandler` 子 trait + `NodeOutcome`（§4.1.3）；`WaitingHuman` 枚举已保留在 00 §0.3 | 不改 `NodeHandler` 签名 |
| 子图执行 | v1.1+ | 新增 `SubgraphHandler`；移除 §4.4.4 的派发前拒绝 | 不改 DSL |
| 字段级输出路由 | v2 | 启用 `GraphNode.outputs` + `GraphEdge.from_output_port`（§4.5.4） | 不改 `NodeHandler` |
| 门控 truthiness | v2 | gate 显式 opt-in 装饰器（如 `@gate(truthiness=True)`），默认仍严格 | 不改 `GateContext` |
| gate 数据转换（transform） | v2 | 独立扩展点，**不复用 gate 返回值**（保持 bool 单义） | 新增 trait |
| 进程内运行时热替换 | 不做 | 若做需对象身份比较 + 线程安全 swap | 修改 §4.7.3 |
| Rust 动态插件（cdylib/wasm） | v2+ | 稳定 FFI 契约后才能注册 handler | 新增注册 API |
| per-graph 命名空间 | v2 | registry key 增加图作用域前缀 | 修改 key 规范 |
| `subgraph` 之外的 v1 不支持节点类型 | v1 | 加载期拒绝（错误码复用 00 §0.4 已有 `DSL_*`，具体由 02 裁定） | — |
